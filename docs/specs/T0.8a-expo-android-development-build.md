# T0.8a: Expo Android development build

## Goal

Create the minimal Android-only Expo SDK 57 application at `apps/mobile` and produce an installable EAS development-client APK. The app starts on a physical Android phone and displays a plain T0.8 placeholder screen. The workspace exposes only the three existing `obd-core` entry points that T0.8b needs, and `pnpm check` typechecks, lints, and tests app workspaces as well as package workspaces. This is the first of two ordered T0.8 specs; it proves the native toolchain and does not complete T0.8 by itself.

## Non-goals

- No BLE scan, connection, `BleTransport`, console, recording, or vehicle session; T0.8b owns those.
- No Expo Router, navigation library, design system, icons, splash assets, storage, foreground service, relay, garage, report, iOS build, web build, EAS Update, store submission, or production profile.
- No generated `android/` or `ios/` directories in the repository. EAS Continuous Native Generation creates Android sources in its build worker.
- No edits to OBD behavior, recordings, roadmap documents, task records, or the completed T0.3 implementation.
- No direct dependency on `@expo/config-plugins` to work around upstream defects. A config-plugin incompatibility is a spec conflict to report.

## Interfaces

### Workspace package surface

`packages/obd-core/package.json` adds source exports without changing any TypeScript implementation:

```json
{
  "exports": {
    "./transport": "./src/transport/types.ts",
    "./elm": "./src/elm/reader.ts",
    "./recording": "./src/recording/format.ts"
  }
}
```

T0.8b imports named exports from these subpaths. There is no default export and no aggregate `index.ts`.

### Mobile command surface

From the repository root:

```text
pnpm -F mobile start       # expo start --dev-client
pnpm -F mobile typecheck
pnpm -F mobile test
pnpm check                 # now includes apps/mobile typecheck, lint, and tests
```

`apps/mobile/eas.json` contains only:

```json
{
  "cli": { "version": "24.7.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "android": { "buildType": "apk" }
    }
  }
}
```

`apps/mobile/app.json` uses Android application ID `com.ev.obd`, Expo slug `obd`, and the EAS owner/project identity selected during `eas init`. It configures the built-in `react-native-ble-plx` plugin as:

```json
["react-native-ble-plx", { "isBackgroundEnabled": false, "neverForLocation": false }]
```

Foreground-only is deliberate for T0.8; the charging foreground service belongs to T2.4. `neverForLocation` remains false because upstream labels it experimental and warns that it can filter scan results. No iOS plugin properties are set.

## Files

Ten implementation files, all in one implementer session:

- `package.json` — modify — include `apps/*` in the recursive `typecheck` and `test` scripts while preserving the existing package and Python bridge checks.
- `tsconfig.json` — modify — keep the root Node-oriented check on `packages/**/*.ts`; the mobile package gets its own Expo TypeScript check.
- `eslint.config.js` — modify — lint `apps/**/*.{ts,tsx}` as well as package TypeScript, using each workspace's tsconfig through project service.
- `pnpm-lock.yaml` — regenerate with pnpm; never hand-edit.
- `packages/obd-core/package.json` — modify — add the three source subpath exports above; no dependency or script change.
- `apps/mobile/package.json` — create — private `mobile` workspace, `expo/AppEntry`, start/typecheck/test scripts, the dependencies listed below, and `obd-core: workspace:*`.
- `apps/mobile/app.json` — create — Android package `com.ev.obd`, Expo slug `obd`, SDK-managed app configuration, and the BLE config plugin settings above. `eas init` may add `owner` and `extra.eas.projectId` here after the user selects the Expo account/organization that owns the project.
- `apps/mobile/eas.json` — create — the single Android development profile above.
- `apps/mobile/tsconfig.json` — create — extend `expo/tsconfig.base`, use strict mode, and include the app `.ts`/`.tsx` files.
- `apps/mobile/App.tsx` — create — one named `App` function plus the required default export adapter for `expo/AppEntry`; render a safe-area-neutral placeholder saying that the T0.8 development build is ready. T0.8b replaces the body with the console.

No asset files are required. Use text only. Do not create `metro.config.js`: Expo SDK 52+ detects pnpm monorepos automatically.

## Dependencies

All application runtime dependencies live in `apps/mobile/package.json`; versions are resolved into `pnpm-lock.yaml`. Add no root dependency.

| Dependency | Requested version | Reason |
|---|---:|---|
| `expo` | `^57.0.0` | Current stable Expo line on 2026-09-23; SDK 57 matches this repository's Node 22.13 floor. |
| `react` | `19.2.3` | Exact React version paired with Expo SDK 57. |
| `react-native` | `0.86.3` | Exact React Native patch selected by current Expo SDK 57 dependency validation (`expo install --check` and Expo Doctor), checked 2026-09-23. |
| `expo-dev-client` | SDK-57-compatible range selected by `expo install` | Required development client because Expo Go cannot load the BLE native module. |
| `expo-file-system` | `~57.0.7` | T0.8b writes the exported `.jsonl` to app cache with the current `File` / `Paths` API. |
| `expo-sharing` | `~57.0.21` | T0.8b opens Android's share sheet for the local `.jsonl` file. |
| `react-native-ble-plx` | `3.5.1` | Latest stable release checked 2026-09-23; supplies Android BLE and its Expo config plugin. |
| `base64-js` | `^1.5.1` | Explicit byte-array/base64 conversion for `react-native-ble-plx`; avoids relying on an undocumented React Native `Buffer` or `btoa` global. |
| `obd-core` | `workspace:*` | Reuses the pure `Transport`, `ElmLineReader`, and recording format without copying protocol logic into the app. |
| `@types/react` | SDK-57-compatible range selected by `expo install` (development) | TypeScript declarations for `App.tsx`; keep aligned with React 19.2.3. |

Installation order from the repository root:

```bash
pnpm --dir apps/mobile add expo@^57.0.0 react@19.2.3 react-native@0.86.3 react-native-ble-plx@3.5.1 base64-js@^1.5.1 'obd-core@workspace:*'
pnpm --dir apps/mobile exec expo install expo-dev-client expo-file-system expo-sharing
pnpm --dir apps/mobile add -D @types/react@~19.2.2
pnpm install
```

The implementer may edit the new manifest first and run equivalent pnpm commands. `expo install` is the authority for SDK-coupled ranges. It must not upgrade to SDK 58, a beta, or a canary. Do not install `eas-cli` in the repository; its own package guidance discourages that. Use `pnpm dlx eas-cli@24.7.0`, and enforce that version in `eas.json`.

## Risks / open questions

- **Largest risk: upstream config-plugin compatibility.** `react-native-ble-plx` 3.5.1 has an open report that its plugin imports `@expo/config-plugins` directly and can fail config evaluation on Expo SDK 56 ([issue #1339](https://github.com/dotintent/react-native-ble-plx/issues/1339)); its README compatibility table is stale. SDK 57 + pnpm must therefore pass `expo config`, `expo-doctor`, and an actual EAS build before BLE code begins. If it fails, stop and return to architecture. Do not add `@expo/config-plugins`, switch pnpm's linker, patch `node_modules`, or use an unreleased Git dependency without a revised spec and explicit dependency decision.
- EAS source upload and signing are external state. The user approved both for this development APK. The Expo account/organization is selected interactively if the CLI offers more than one. No Expo access token belongs in the repository.
- The application ID becomes part of installed-app identity. The user selected `com.ev.obd`; the implementer must not substitute another ID.
- SDK 57 uses React Native's mandatory New Architecture. The actual EAS build, not the package README's old compatibility table, is the gate for `react-native-ble-plx`.

No material design decision remains open. The build still requires the user to select an Expo account/organization if `eas init` presents more than one authorized owner; that is credential routing, not an application design choice.

## Decisions

- Split T0.8 into ordered T0.8a (native scaffold/build) and T0.8b (BLE console/recording) so each spec fits one implementer session and no spec exceeds ten implementation files.
- Use stable Expo SDK 57, not a prerelease, and validate the BLE plugin with the real cloud build before accepting compatibility.
- Use Expo CNG and automatic monorepo support; do not commit generated native projects or a custom Metro configuration.
- User decision: Android application ID is `com.ev.obd`; Expo slug is `obd`.
- User decision: EAS Build source upload and Expo-managed Android development-keystore generation/storage are authorized.
- Revision after the first implementer stop: use React Native 0.86.3 because current SDK 57 validation selects that patch; run Expo Doctor from the real mobile working directory; verify BLE manifest mods with read-only `expo config --type introspect`, not unevaluated `--type prebuild` output.
- EAS authentication is still a prerequisite: `whoami` reported `Not logged in`, and the user requested interactive login before project initialization/build.
