# T2.3b: Targeted Equinox watch session (Gate B follow-up to T2.3a)

## Goal

This task has three parts, and all three are needed before the user's next laptop session at the 2024 Equinox EV.

1. **Recorder ordering fix.** `tools/spike/discover.py` writes every `tx` line before the first BLE write byte. A stalled `write_gatt_char` can then no longer let the reply get recorded first, which is what happened at lines 49775/49776 of the 2026-09-23 discovery recording.
2. **Local replay check goes green again.** `packages/obd-core/test/recordings.test.ts` exempts exactly one known defect: that tx line in that file, identified by SHA-256. Every other recording, including every future one, still gets the full check. Local `pnpm check` is green again with the gitignored recording on disk.
3. **Targeted watch tool.** A new tool, `uv run tools/spike/targeted.py`, runs a ~15 min watch with no phase-B scan. It re-runs the proven T2.3a phase A, then polls a checked-in watch list derived from the T2.3a phase-B positives. The list has two parts:
   - a **core** set, polled every cycle: the 17 named `CB` DIDs;
   - a **rotating** set: the remaining `17` and multi-frame `CB` positives, polled in time-sliced rotation so that every DID is read at least once in every state.
   The user marks the same five states with Enter. The tool refuses to leave the charging state before 5 minutes, and refuses to leave any state before one full rotation.

Test-visible outcome here: ruff and pytest pass offline with a fake BLE client. The tests cover the ordering fix, the allowlist (no VIN, only `AT`/`01`/`09`/`22`), rotation, state enforcement, and every watch-list DID's citation, checked against the local recording when it is on disk. `pnpm check` is green locally. Hardware-visible outcome, NOT RUN until the user's session: a strictly replayable recording `fixtures/recordings/chevrolet-equinox-ev-2024/<date>-discovery-targeted.jsonl` with at least 5 minutes of charging, from which Claude fills a new run-card section. Gate B stays `NOT DECIDED` for the owner.

## Interfaces

### 1. `tools/spike/discover.py`: record `tx` before the write

```python
# before (lines 115-131)
    async def _once(self, cmd: str) -> str:
        self.buf.clear()
        self.prompt.clear()
        payload = (cmd + "\r").encode(CODEC)
        for i in range(0, len(payload), CHUNK):
            await self.client.write_gatt_char(self.write_char, payload[i:i + CHUNK],
                                              response=not self.without_response)
        self.rec.event("tx", cmd + "\r")
        try:
            await asyncio.wait_for(self.prompt.wait(), CMD_TIMEOUT_S)
        except TimeoutError: ...
        except BaseException as e: ...   # interrupted note, re-raise
        return "".join(self.buf)

# after
    async def _once(self, cmd: str) -> str:
        self.buf.clear()
        self.prompt.clear()
        payload = (cmd + "\r").encode(CODEC)
        # tx first: a notification can arrive while write_gatt_char is still awaiting (2026-09-23 line 49775).
        self.rec.event("tx", cmd + "\r")
        try:
            for i in range(0, len(payload), CHUNK):
                await self.client.write_gatt_char(self.write_char, payload[i:i + CHUNK],
                                                  response=not self.without_response)
            await asyncio.wait_for(self.prompt.wait(), CMD_TIMEOUT_S)
        except TimeoutError: ...          # unchanged
        except BaseException as e: ...   # unchanged: "timeout waiting for '>' after <cmd> (interrupted: <type>)", re-raise
        return "".join(self.buf)
```

Why the writes move inside the `try`: once the `tx` line is written first, a write that raises (for example a BLE drop) would otherwise leave an orphan `tx` with no rx and no note, and the partial file would fail replay. Inside the `try`, it gets the existing interrupted note, which `recordings.test.ts` `timedOut()` already accepts. Ordering is guaranteed because `Recorder.event` is synchronous, and the notify callback can only run at the first `await`, which comes after the `tx` line is flushed. `CMD_TIMEOUT_S` still bounds only the wait for `>`, as before. Net line count: unchanged (299).

### 2. `packages/obd-core/test/recordings.test.ts`: one SHA-keyed exemption

```ts
// before
function replayTest(file: string): void          // it(...) reads, replays, asserts '>' per tx unless timedOut()

// after
// Known recorder defect, keyed by file SHA-256 → 1-based tx line whose '>' was recorded on the line just
// before it (discover.py wrote tx after the BLE write returned; fixed in T2.3b). Only this line of this exact file.
const EARLY_PROMPT: Readonly<Record<string, number>> = {
  "520fc8fba7dd2453474a8471c22dd50dfb946c360cbde46d5d3f1a648e92cc53": 49776, // chevrolet-equinox-ev-2024/2026-09-23-discovery.jsonl
};
async function replay(lines: RecordingLine[], earlyPrompt?: number): Promise<void>
function replayTest(file: string): void          // reads bytes, sha256 (node:crypto), replay(lines, EARLY_PROMPT[hash])
```

`replay` behaves exactly like today's loop body, with one addition at the tx whose 1-based line equals `earlyPrompt`. There, instead of `expect(completed.length > 0)`, it asserts the defect's exact shape:
- `lines[i - 1]` is an `rx` whose data contains `>`;
- `completed.length === 0`.

It then continues. After the loop, if `earlyPrompt` was given, it asserts that line was actually reached, so a stale entry fails. Nothing else changes: the 120 s timeout, `timedOut()`, the synthetic and recordings `describe`s, and the `it.skip` NOT RUN line all stay as they are.

Three new in-memory cases, run in CI, with no fixture file (a file under `fixtures/synthetic/` would be replayed as must-pass):
- (a) a 5-line recording `tx A`, `rx ">"`, `rx "OK\r\r>"`, `tx B`, `tx C` + `rx ">"` fails `replay(lines)` with the `no '>'` message for line 4;
- (b) the same recording passes `replay(lines, 4)`;
- (c) `replay(lines, 1)` fails, because line 1 is not preceded by an `rx` with `>`, and a correct recording given an unused `earlyPrompt` fails the "reached" assertion.

The implementer picks the exact literals; the three behaviors are the contract.

Why this does not weaken the check: the exemption applies only to a file whose bytes hash to one value, only at one tx line, and only if the defect has the recorded shape. Every other file gets the unchanged check. That includes the two T0.2 recordings, the synthetic fixture, and every future recording, even one with the same defect. Case (a) proves that in CI.

### 3. `tools/spike/targeted.py` (new; PEP 723 header identical to discover.py; `bleak` imported only in `main`)

```python
from discover import CAR, STATES, Elm, select, sweep
from go import ask, find_dongle, next_out_path
from spike import SERVICE, Recorder

WATCH_LIST = os.path.join(os.path.dirname(os.path.abspath(__file__)), "targeted_watch.json")

    # did makes discover.check_allowed(f"22 {did}") pass, no (module, did) appears twice across both lists.
async def watch_targeted(elm: Elm, rec: Recorder, core: list[tuple[str, str]],
                         rotate: list[tuple[str, str]], marks: "asyncio.Queue[str]") -> None: ...
def main() -> None: ...
```

**Command line.** `uv run tools/spike/targeted.py` (argparse with no options, only for `--help`). The prompts are the same as discover.py: dash SOC and ambient. Then `find_dongle()`, `next_out_path(CAR, <local date>, "discovery-targeted")`, connect, and pick the characteristics exactly as `discover.main` does. The first meta line has the same keys as discover.py, with `script: "tools/spike/targeted.py"`. Before connecting, print the plan: phase A (~20 s), then the watch with its core and rotate counts, the estimated rotation seconds, and the per-state minimums.

**Phase A.** `await sweep(elm, rec)`, unchanged: meta `phase: "A"`, init, Mode 01 walk, `ATSP7`/`ATCP 18`, per-module select + Mode 09, and `elm.fatal = True`. Reusing it keeps the one init sequence that is proven on this car (T2.3a lines 2–537, 17 s) and gives a fresh standard snapshot. There is no meta `phase: "B"`.

**Phase C: watch** (`watch_targeted`). Order of steps:

1. Write meta `{"phase": "C", "watch_list": "tools/spike/targeted_watch.json", "watch_list_sha256": <sha256 of the JSON file bytes>, "core": <n>, "rotate": <n>, "rotate_s": ROTATE_S, "charge_min_s": CHARGE_MIN_S}`.
2. For each state in `STATES`:
   - write meta `{"phase": "C", "state": s}`;
   - reset the per-state counters (elapsed and rotating DIDs polled since the mark);
   - loop cycles.
3. One cycle:
   - send `ATRV`;
   - send every core entry in list order;
   - then send rotating entries starting at a pointer that persists across cycles and states, wrapping at the end, until `ROTATE_S` has elapsed since the rotating slice started (checked before each send; at least one rotating DID per cycle).
   - Module selection: before sending an entry whose module differs from the currently selected one, call `select(elm, module)`. The selection is forgotten at the start of each cycle, so every cycle re-selects its first module.
4. After each cycle, print: state, time in state, cycles, rotating DIDs polled since the mark out of `len(rotate)`, and for the charging state `charging m:ss of 5:00, do not unplug yet`.
5. Marks are taken between cycles only, as in T2.3a. A mark is **accepted** only if both hold:
   - rotating DIDs polled since the mark ≥ `len(rotate)`;
   - in `CHARGE_STATE`, elapsed ≥ `CHARGE_MIN_S`.

   Otherwise the tool **ignores** it:
   - write meta `{"phase": "C", "note": "early mark ignored", "state": s, "elapsed_s": <int>}`;
   - print what is still missing and "press Enter again when done";
   - keep polling.
6. After the mark that ends `unplugged`, write meta `{"phase": "end"}`.

**Stdin.** Because marks can be ignored, the reader task reads lines until EOF or until the watch ends, not exactly `len(STATES)` lines:

```python
while line := await asyncio.to_thread(sys.stdin.readline):
    await marks.put(line)
```

At EOF it stops (no endless empty marks). If the reader is still blocked when the watch ends, print "Press Enter to exit." (the existing discover.py pattern).

**Instructions** (wording is the implementer's):
- idle: HVAC off, Ready, Park. Wait for "full rotation done". Set the heater to max and press Enter once hot air flows.
- heater max on: after "full rotation done", heater off, then press Enter.
- heater off: after "full rotation done", plug in the home charger. Press Enter once the car or charger shows charging. If it does not start charging within about 1 minute in Ready, switch the car off, wait for charging, then press Enter. Leave the laptop in the car.
- plugged in and charging: keep charging until the console says 5:00 reached and the rotation is done, then unplug and press Enter.
- unplugged: after "full rotation done", press Enter to finish.

**Abort and interruption.** Same as discover.py, through `Elm.send`: `LV RESET` or `UNABLE TO CONNECT` → meta `aborted:` and exit, and the partial file stays valid; Ctrl+C or a BLE drop → interrupted note.

## Time budget

Cycle = `ATRV` 0.044 s + select `CB` 0.09 s + core 1.47 s + select `17` when the pointer is in `17` (0.09 s) + `ROTATE_S` 6 s + the overshoot of the last request (~0.1 s). That is **≈ 7.8 s per cycle**, so each core DID is sampled about every 8 s (T2.3a: ~15 s).

| heater off (1 rotation, plus walking and plugging in) | ~2 min | ~2 min |
| plugged in and charging (≥ 5 min; ≥ 2 rotations even with `17` silent) | 5–5.5 min | 5–5.5 min |
| unplugged (1 rotation; slower if the car is off) | 1.2–2.2 min | 1.7–2.7 min |
| Total | **≈ 12–13.5 min** | **≈ 13.5–15 min** |

Why rotation, not per-state full sweeps. A full sweep at each state mark samples every rotating DID right after the switch, during the transient (heater ramp, charger handshake), and then leaves ~1 min of core-only polling. Rotation spreads samples through the state at the same cost, keeps the core cadence constant, and is time-sliced. If `17` goes silent with the car off, only the rotation slows; the core cadence does not. Larger `ROTATE_S` shortens rotations slightly (8 s → ~63 s for the recommended list) but halves the core cadence. 6 s is the chosen middle. A lower bound of one full rotation per state (not two) keeps the session near 15 min. The charging state gets 2–4 rotations.
