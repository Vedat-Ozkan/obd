# T2.10c C1: Prepare pinned Wrangler on fresh CI runners

## Goal

Make the existing C1 real-D1 E2E gate run on a fresh Linux runner with no prior pnpm `dlx` cache. Prepare Wrangler **4.142.0** explicitly during CI setup, before `pnpm check`; the fixture harness continues to launch only the already prepared exact version. This is one implementation session and a separately reviewable C1 software repair. Governing backend scope and all existing expectations remain in [T2.10c-hosted-deepseek-eval.md](T2.10c-hosted-deepseek-eval.md).

## Interfaces / design

Public Worker and package interfaces stay as defined by the governing C1 spec. The setup contract is:

```bash
pnpm dlx wrangler@4.142.0 --version
pnpm check
```

In `.github/workflows/check.yml`, set job-level `XDG_CACHE_HOME: ${{ runner.temp }}/t210-ci-cache` so preparation and all tests share the same cache root. Add a named pinned-Wrangler preparation step after workspace installation and before `pnpm check`. Keep the existing Node 22.13.0, pnpm 9.15.9, Python, uv and frozen workspace/bridge installs. Disable Wrangler metrics for preparation with `WRANGLER_SEND_METRICS: 'false'` (job or step environment); tests already disable them. No cache restore is required for this tool. Failure preparing the exact version must fail setup.

`cachedWrangler()` continues to inspect manifests under `${XDG_CACHE_HOME}/pnpm/dlx` and execute the exact cached `node_modules/wrangler/bin/wrangler.js` directly. Add only a missing-directory guard and actionable prerequisite message: explain that Wrangler 4.142.0 must be prepared with `pnpm dlx wrangler@4.142.0 --version` using the same `XDG_CACHE_HOME` before tests. Use that message both when the cache directory is absent and when no matching package is present. Do not catch unrelated permission/I/O errors as a successful prerequisite check, fall back to another version, install tools or alter runtime fixture logic.

Update the backend README's reproducible software gates with an explicit first-use preparation command and shared-cache explanation. CI setup and owner CLI preparation may install the previously approved tool; **test execution may not install it**. This clarifies the existing no-install test rule without changing vehicle/provider behavior.

```bash

export CI=true

pnpm vitest run tools/summary-backend/worker.test.ts > "$T210_CI_ROOT/missing-cache.log" 2>&1
```

Expected pre-edit evidence: nonzero exit and ENOENT at `cachedWrangler`, matching the owner CI failure. Expected post-edit evidence, rerunning the last command with the cache still empty: nonzero exit and the exact-version preparation instruction with no ENOENT masking it.
