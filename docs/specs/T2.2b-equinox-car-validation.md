# T2.2b: New Equinox car validation and signal review

## Goal

Collect a new, immutable 2024 Equinox EV recording at a dashboard SOC distinct from the two 70% spike captures; compare all answered OBDb signals with contemporaneous dash observations and the earlier recordings; then update the per-signal evidence table and tier map only where the observations support it. The owner-facing procedure is `docs/obdb-verification-2026-09.md`. Prepare the final upstream correction draft from the same evidence. T2.2 remains open for actual upstream PR submission under ADR-010.

## Non-goals

- Driving while watching a laptop or phone, inducing a fault, clearing codes, changing ECU sessions, or opening the HV system.
- Assuming that the phone debug console or its one-button capture can send the 29-bit Equinox setup. Its `ALLOWED_AT_COMMANDS` excludes `ATSP7`, `ATCP`, `ATSH`, `ATCRA`, and flow-control commands; its fixed capture has no Mode 22.
- Promoting cell-voltage IDs from dash SOC alone. The dash does not display individual cell voltage. A physically plausible range or min≤avg≤max by itself is insufficient independent evidence.
- Hand-editing a recording, reading or committing an unredacted copy, editing the upstream vendored signalset in place, or publishing an external PR.

## Interfaces

No new public API is required for capture. `tools/spike/go.py` invokes the existing fixed `tools/spike/spike.py` 2024 Equinox command list; `tools/spike/redact_vin.py` creates a new `*.redacted.jsonl` copy; `pnpm replay` (or T2.1's Node fallback) produces the user-visible decoded artifact. The T2.2a `equinoxEv2024Evidence` map may gain a signal ID only after the run-card table cites a redacted recording path, exact line numbers, and a plausibility check. It may lose an SOC ID if the new dash observation disagrees. The importer always remains `community` at import.

If the new capture cannot establish an independent cell-voltage check, leave AVG/MIN/MAX `community` and say so in the note. A second state showing a sensible voltage change with SOC is supporting evidence; a cell-voltage promotion also needs a separate reference, such as a same-session per-group reading from a sourced, redacted recording. No such per-group DID is in the committed Equinox signalset or committed recordings today, so adding it to a tool requires a separate sourced spec after a permissible recording exists. This spec does not add it from the local, unredacted discovery data.

## Files

- `fixtures/recordings/chevrolet-equinox-ev-2024/<date>-spike.redacted.jsonl` (or `-spike-2.redacted.jsonl`, etc.) — add only the tool-produced copy, with the actual path chosen by `go.py`; never edit it. The raw sibling remains local and gitignored.
- `docs/obdb-verification-2026-09.md` — fill the recording path, dash/state/time table, per-signal comparison, line citations, PASS/FAIL/NOT RUN, and final draft upstream correction. The architect's run card already gives the procedure.
- `packages/obd-core/src/vehicles/obdb/equinox.ts` — modify only if the new evidence changes the T2.2a tier map; every added ID needs a recording citation and independent check. Downgrade a disagreeing SOC ID.
- `packages/obd-core/test/obdb-equinox.test.ts` — extend recording-backed E2E assertions before any tier-map change. Tests must show the user-visible tier and number via replay.
- `packages/obd-core/scripts/replay.ts` — modify only if needed for a sound public replay of the new recording; no change is planned.

At most five implementation files. No new dependency. No `apps/mobile`, guard, relay, vendored OBDb JSON, or broader discovery-tool change. The exact capture filename is a hardware result, not a planned constant.

No isolated tests are specified; replaying the real recording through the public entry point covers the behavior. No Python source changes are planned, so the redactor and recorder are verified by their existing checks plus the generated artifact.

## Risks / open questions

- Largest risk: a second SOC reading may agree with the dash while cell voltage still lacks an independent reference. The correct outcome is two verified SOC signals, three community cell signals, and a specific cell-check follow-up.
- The existing `go.py` runs the full fixed T0.2 list, including VIN `0902`, before Mode 22. Use the redactor on the original and share only the resulting copy; do not paste printed raw rows into an issue or chat.
- A late prompt after a timeout could make subsequent rows ambiguous. The replay and line-by-line status determine whether each reading is usable. Preserve partial files and rerun to a new path; never repair a recording by hand.
- One 2024 car supports a 2024 correction proposal but not a guarantee for every model year. The draft should state this limit. Upstream PR publication is pending owner direction.

## Decisions

- Use the existing laptop `go.py`/`spike.py` capture because it already sends the exact sourced 29-bit read sequence and creates an immutable recording. A phone-based T2.2 capture would first need a separately reviewed extension to the mobile console allowlist and UI; this session does not depend on it.
