# T0.5: `obd-core` standard decoding: J1979 table, Mode 01 values, supported-PID bitmaps, readiness, DTC lists, Mode 09 VIN / CAL ID / ECU name

## Goal

Turn the per-ECU ISO-TP messages that `Elm327Session` (T0.4) returns into typed values. Every formula and bit layout traces to a source checked into the repo. The work comes in three stages, each its own implementer session and review gate:

- **Stage A (goes first).** Vendor OBDb's SAEJ1979 signalset and add a "J1979 conventions" section to `docs/ELM327.md`. Then add the table-driven Mode 01 file (`j1979.ts`), supported-PID bitmap decoding, and readiness decoding from PIDs 01 and 41.
- **Stage B.** Mode 03/07/0A DTC lists with P/C/B/U decoding. Mode 09 VIN with a check-digit status, CAL IDs, and ECU names. `pnpm replay` prints the decoded values.
- **Stage C (conditional).** Mode 02 freeze frame. It can only start after a hardware capture shows the reply layout (open question 2).

What a test sees when this is done:
- `decodeSupported` on the tracked Equinox `0100`/`0120`/`0140` replies returns each module's PID list. For example, module `17` gives `01 0D 1C 1F 20`.
- `decodeReadiness(0x01, …)` on the tracked `0101` replies says the same for all five modules: MIL off, 0 DTCs, spark layout, and one monitor, `components`, complete.
- `decodeDtcList` on the tracked `03`/`07`/`0A` replies returns "no DTCs" per module, and negative response `0x11` from modules `17` and `CB` on `0A`.
- `decodeVin` on the tracked, redacted `0902` replies returns 17 characters with status `masked` for modules `17` and `28`. The test never writes the VIN as a literal. The 49 CFR 565 sample VIN decodes `valid`.
- `pnpm replay` on the spike recording prints `decoded …` lines for everything the car actually answered, and no VIN characters.
- A table-driven test decodes every PID in `j1979.ts` from known bytes. A second test checks every row of the table mechanically against the vendored OBDb JSON.

## Non-goals

- **No request orchestration.** Nothing here decides which commands to send, walks the bitmaps over the wire, or sets up `ATCRA` per module for `090A`. Decoders take one `Frame` and return one result. The walk and the codes-report flow are T0.9; the report model and the "recently cleared" heuristic are T0.7. (`docs/ARCHITECTURE.md` calls `supported.ts` a "bitmap walk". Stage B edits that line.)
- **No multi-PID responses** (`010C0D…`). A payload longer than one PID's length is a `length` failure. The drive logger will need its own parser.
- **No Mode 01 PIDs beyond the table below.** In particular: no `9A` (hybrid/EV voltage and current, a multi-field signal with support flags), no `D2`, and no ICE PIDs (`0C`, `0D`, `1F`, …), even though the Equinox answers some of them. No Mode 09 `00` bitmap, `06` CVN, or `08`/`0B` in-use tracking. No Mode 06.
- **No NRC interpretation.** A negative response is reported with its code byte only (T0.4 non-goal, unchanged).
- **No zod schemas.** The outputs are built by our code from bytes, not parsed from outside input. The package boundary where they get serialized is T0.7's `CodesReport`, and T0.7 defines that schema.
- **No OBDb importer and no runtime JSON loading.** The vendored JSON is a checked-in source, used by a test. Importing OBDb signalsets is T2.1.
- **No model-year decoding from VIN position 10.** The year code repeats every 30 years (49 CFR 565.15 Table VII). No WMI or manufacturer lookup.
- **No change to `Elm327Session`, `isotp.ts`, the write guard, `recordings.test.ts`, or any recording.** No `package.json` `exports` change: T0.7 lives in `obd-core` and imports relatively.
- **No logging** in `src/`, as in T0.4.

## Sourcing decision (hard rule 1)

SAE J1979 and ISO 15031-5 are paywalled, so no primary copy can be checked in. Recommendation (open question 1). Sources rank in this order, and every row of the new `docs/ELM327.md` section names its source:

1. **Tracked recordings** (`fixtures/recordings/chevrolet-equinox-ev-2024/*.redacted.jsonl`). These are real behavior and outrank everything else.
2. **Vendored OBDb SAEJ1979 signalset.** Repo `github.com/OBDb/SAEJ1979`, commit `d3259214a9e0340c4a6cff9ec5f8ff5953eee6f2` (2025-11-29), file `signalsets/v3/default.json`, license **CC-BY-SA-4.0** (confirmed through the GitHub license API and the repo's `LICENSE`). It is copied verbatim to `packages/obd-core/vehicles/saej1979/`. Its Mode 01 entries are the source for per-PID byte length, scaling (`mul`/`div`/`add`), unit, readiness bit positions (`bix`), and the `1C` enum. A test compares every row of `j1979.ts` with it, so the table cannot drift from its source.
3. **`docs/ELM327.md` §J1979 conventions (new)** covers what OBDb does not encode: the bitmap bit order, the response echo, readiness polarity and the spark/compression C/D layouts, the DTC count byte and 2-byte encoding, and the Mode 09 layouts. Each row cites a recording where one exists. Otherwise it cites Wikipedia "OBD-II PIDs", revision `oldid=1374011962` (2026-09-09, CC-BY-SA-4.0), marked **(secondary)**. The rows paraphrase facts; no tables are copied.
4. **VIN character set and check digit:** 49 CFR 565.15(c), Tables III–VI (eCFR, US government work, public domain), including its sample VIN `1G4AH59H45G118341` (check digit `4`).

**Conflicts found and resolved** (recorded in the new section):
- **PID 01 byte D polarity.** OBDb's `01/01` marks `EGR_RDY`…`CAT_RDY` (bix 24–31) as `noyes`, meaning 1 = ready. That contradicts Wikipedia ("for completeness a bit set to 0 indicates complete") and OBDb's own `01/41` D-byte `*_CMPL` `yesno` and `01/01` B-byte `*_RDY` `yesno`. **We follow Wikipedia: bit set = incomplete, in bytes B and D, for both PIDs.** The fix goes upstream as an OBDb issue (ADR-010), noted in the task record, not in this diff.
- **C4/D4 on spark engines.** Wikipedia says gasoline particulate filter and calls "A/C refrigerant" the older reading. OBDb says `ACRF`. **We use `gpf`.** This matters little here: the Equinox sets no C/D bits.

**Licensing consequences.**
- The JSON and OBDb's `LICENSE` sit in their own directory with an attribution `README.md`, and stay CC-BY-SA-4.0 (ADR-010).
- ADR-010 names `vehicles/<make>-<model>/`. `saej1979/` is the generic-standard sibling. It needs no ADR change, and the architect's summary says so.
- `j1979.ts` carries only facts taken from that data: byte counts, scale factors, and the `1C` code-to-short-name map. It has an attribution header comment. If it were ever judged an adaptation, ShareAlike would make that one data file CC-BY-SA. That fits ADR-010's reading and leaves the decoding code under the project's terms. This is not legal advice (as in ADR-010).
- Wikipedia text is not copied, only cited.

## Interfaces

All exports are named. Relative imports use `.js` extensions. Nothing under `src/obd/` imports `node:*`, React Native, or BLE, or calls `fetch` or `console`. Every decoder is pure, takes one `Frame` (T0.4 `src/elm/isotp.ts`), and returns a result tagged with `frame.ecu`. Callers map over `response.frames`, one result per answering module.

### Stage A

#### `src/obd/response.ts` — create

```ts
import type { Frame } from "../elm/isotp.js";

export interface DecodeFailure {
  ok: false;
  ecu: string;
  reason: "negative" | "echo" | "length" | "format" | "unknown-pid";
  code?: number;   // present iff reason === "negative": frame.negative.code
}

/** Failure if the frame is negative, or its data does not start with `echo` (e.g. [0x41, pid]); else undefined. */
export function checkEcho(frame: Frame, echo: readonly number[]): DecodeFailure | undefined;
```

Checking the echo covers T0.4's resync risk: a late `>` from a timed-out command can pair a reply with the wrong request, and the echoed PID catches that.

#### `src/obd/j1979.ts` — create — the table plus scalar decode

```ts
export type Unit = "percent" | "degC" | "km" | "min" | "V" | "count" | "enum";

export interface PidDef {
  pid: number;        // 0x31
  id: string;         // OBDb signal id, the cross-check key: "CLR_DIST"
  bytes: 1 | 2 | 4;   // raw = big-endian unsigned over `bytes` bytes after the 41 <pid> echo
  mul: number; div: number; add: number;   // value = raw * mul / div + add (OBDb fmt semantics; absent = 1, 1, 0)
  unit: Unit;
}

/** Rows: 1C 21 30 31 42 46 4D 4E 5B A6 B2 (table below). */
export const MODE01_PIDS: readonly PidDef[];
/** PID 1C code -> OBDb map `value` string (e.g. 5 -> "NO OBD"), all codes in the vendored map. */
export const OBD_STANDARDS: Readonly<Record<number, string>>;

export interface PidReading {
  ok: true; ecu: string; pid: number; id: string;
  value: number;      // unrounded; rounding is the renderer's job
  unit: Unit;
  label?: string;     // unit "enum" only, when OBD_STANDARDS has the code
}

/** checkEcho [0x41, pid]; pid not in MODE01_PIDS -> "unknown-pid"; data.length !== 2 + bytes -> "length". */
export function decodePid(pid: number, frame: Frame): PidReading | DecodeFailure;
```

The table. Every row equals the vendored OBDb `01/<pid>` signal, and the `docs/ELM327.md` §Mode 01 table where that table has the row.

| pid | id | bytes | mul | div | add | unit | Notes |
|---|---|---|---|---|---|---|---|
| 1C | OBDSUP | 1 | 1 | 1 | 0 | enum | label from `OBD_STANDARDS` |
| 21 | MIL_DIST | 2 | 1 | 1 | 0 | km | |
| 30 | WARM_UPS | 1 | 1 | 1 | 0 | count | |
| 31 | CLR_DIST | 2 | 1 | 1 | 0 | km | |
| 42 | VPWR | 2 | 1 | 1000 | 0 | V | |
| 46 | AAT | 1 | 1 | 1 | −40 | degC | |
| 4D | MIL_TIME | 2 | 1 | 1 | 0 | min | |
| 4E | CLR_TIME | 2 | 1 | 1 | 0 | min | |
| 5B | BAT_SOC | 1 | 100 | 255 | 0 | percent | hybrid/EV pack remaining charge |
| A6 | ODO | 4 | 1 | 10 | 0 | km | EV-relevant; the Equinox answers it (local discovery only) |
| B2 | BAT_SOH | 1 | 100 | 255 | 0 | percent | traction pack SOH; synthetic only (Equinox `01A0` bitmap has no B2) |

`A6` and `B2` are the "others in the checked-in J1979 table" from the PLAN row. They are the standard PIDs a used-EV report needs on makes other than GM. `9A`/`D2` are excluded (Non-goals).

#### `src/obd/supported.ts` — create

```ts
export const BITMAP_PIDS: readonly number[];  // [0x00, 0x20, 0x40, 0x60, 0x80, 0xA0, 0xC0]
export interface Supported { ok: true; ecu: string; base: number; pids: number[] }  // ascending; base+0x20 included when flagged
/** base not in BITMAP_PIDS -> "unknown-pid"; checkEcho [0x41, base]; data.length !== 6 -> "length". */
export function decodeSupported(base: number, frame: Frame): Supported | DecodeFailure;
```

Bit order: the MSB of byte A is `base+1` and the LSB of byte D is `base+0x20` (§J1979 conventions).

#### `src/obd/readiness.ts` — create

```ts
export type MonitorId =
  | "misfire" | "fuel" | "components"                                         // byte B, both layouts
  | "catalyst" | "heatedCatalyst" | "evap" | "secondaryAir" | "gpf"            // spark C0..C4
  | "o2Sensor" | "o2Heater" | "egrVvt"                                         // spark C5..C7 (C7 both layouts)
  | "nmhcCatalyst" | "noxScr" | "boostPressure" | "exhaustGasSensor" | "pmFilter"; // compression C0,C1,C3,C5,C6

/** Index = bit number 0..7 of byte C/D. undefined = reserved (compression C2, C4). */
export const SPARK_MONITORS: readonly MonitorId[];
export const COMPRESSION_MONITORS: readonly (MonitorId | undefined)[];

export interface Monitor { id: MonitorId; complete: boolean }
export interface Readiness {
  ok: true; ecu: string; pid: 0x01 | 0x41;
  mil?: boolean;        // PID 01 only: A7
  dtcCount?: number;    // PID 01 only: A6..A0
  ignition: "spark" | "compression";  // B3
  /** Only monitors whose availability bit (01) / enabled bit (41) is set, in order B0, B1, B2, C0..C7.
   *  complete = the matching completeness bit (B4..B6, D0..D7) is 0. Reserved bits are ignored. */
  monitors: Monitor[];
}
/** checkEcho [0x41, pid]; data.length !== 6 -> "length". Byte A of PID 41 is not read. */
export function decodeReadiness(pid: 0x01 | 0x41, frame: Frame): Readiness | DecodeFailure;
```

### Stage B

#### `src/obd/dtc.ts` — create

```ts
export type DtcMode = 0x03 | 0x07 | 0x0a;
export interface DtcList { ok: true; ecu: string; mode: DtcMode; dtcs: string[] }  // e.g. ["P0133", "U0158"]
/** Two bytes -> "P0133": A7..A6 -> P/C/B/U, A5..A4 -> first digit 0-3, then A3..A0, B7..B4, B3..B0 as hex (uppercase). */
export function decodeDtc(a: number, b: number): string;
/** checkEcho [mode + 0x40]; data.length < 2 or data.length !== 2 + 2 * data[1] -> "length"; 00 00 pairs skipped. */
export function decodeDtcList(mode: DtcMode, frame: Frame): DtcList | DecodeFailure;
```

#### `src/obd/vin.ts` — create — Mode 09 text infotypes

```ts
export type VinStatus = "valid" | "check-digit-mismatch" | "masked";
export interface VinResult { ok: true; ecu: string; vin: string; status: VinStatus }
/** checkEcho [0x49, 0x02]; data.length !== 20 -> "length"; data[2] !== 1 or any of the 17 chars outside
 *  [0-9A-HJ-NPR-Z] -> "format". chars 12..17 === "000000" -> "masked" (ADR-017 mask; check digit not computed).
 *  Otherwise vin[8] === vinCheckDigit(vin) ? "valid" : "check-digit-mismatch". */
export function decodeVin(frame: Frame): VinResult | DecodeFailure;
/** 49 CFR 565.15(c): expected position-9 character ("0"-"9" or "X"); undefined if vin is not 17 VIN characters. */
export function vinCheckDigit(vin: string): string | undefined;

export interface CalIds { ok: true; ecu: string; calIds: string[] }
/** checkEcho [0x49, 0x04]; n = data[2]; data.length !== 3 + 16n -> "length"; each 16-byte block: NULs removed,
 *  any remaining byte outside 0x20-0x7E -> "format". */
export function decodeCalIds(frame: Frame): CalIds | DecodeFailure;

export interface EcuName { ok: true; ecu: string; name: string }
/** checkEcho [0x49, 0x0A]; data.length !== 23 -> "length"; data[2] !== 1 -> "format"; 20 bytes, NULs removed,
 *  remaining bytes 0x20-0x7E else "format". Spike: module 45 -> "GWM-Gateway". */
export function decodeEcuName(frame: Frame): EcuName | DecodeFailure;
```

**Why "check-digit-mismatch" and not "invalid".** 49 CFR 565 binds US-market vehicles only, so an imported VIN can legitimately fail the check. **Why "masked" is decided before the check digit.** Committed recordings carry `000000` at positions 12–17 (ADR-017), so their check digit cannot be verified. A real VIN with serial `000000` would also read `masked`, which is an accepted risk.

**ECU name (`090A`)** is an addition to the PLAN row, which says "VIN and CAL ID". It reuses the same text rule, and it is the only non-VIN Mode 09 text in the tracked evidence (spike lines 85–90). The report needs it to name the module that reported each value.

**VIN privacy (ADR-014, ADR-017).** The VIN string exists only in the returned object. `src/` never logs it. `pnpm replay` never prints a VIN character, not even for `format` failures. Tests on recorded data assert structure only, with no VIN literal. Synthetic VINs (the 49 CFR sample and variants built from it, and the existing `1C4SYNTHETICVIN00`) may appear as literals.

#### `scripts/replay.ts` — modify

After each block's frame, dropped, and text lines, add one line per frame, `  decoded <ecu> <text>`. It is emitted when the normalized command (spaces removed, uppercase) is one of:

| Command | Decoder | `<text>` on success |
|---|---|---|
| `01` + a PID in `BITMAP_PIDS` | `decodeSupported` | `supported <PIDs as 2-hex uppercase, space-separated>` or `supported none` |
| `0101`, `0141` | `decodeReadiness` | `readiness pid=<01\|41>[ mil=<on\|off> dtcs=<n>] ignition=<spark\|compression>` then ` <id>=<complete\|incomplete>` per monitor |
| `01` + a PID in `MODE01_PIDS` | `decodePid` | `<id> <value> <unit>`, value `String(Math.round(v * 1000) / 1000)`; enum: `<id> <code>[ (<label>)]` |
| `03`, `07`, `0A` | `decodeDtcList` | `dtcs <codes space-separated>` or `dtcs none` |
| `0902` | `decodeVin` | `vin status=<status>` (no characters) |
| `0904` | `decodeCalIds` | `cal-ids <ids space-separated>` or `cal-ids none` |
| `090A` | `decodeEcuName` | `ecu-name <name>` |

Failures print `decoded <ecu> negative code=<hh>` or `decoded <ecu> invalid <reason>`. Other Mode 01 PIDs, Mode 22, and AT commands print no decoded line. The existing redaction, the summary line, and the exit codes do not change.

## Risks

- **Secondary sources.** Readiness polarity, the C/D layouts, the DTC encoding, and the Mode 09 layouts rest on Wikipedia, cross-checked against OBDb and the recordings where those exist. Where both are silent (compression layout, CAL ID count byte), the only check is the local discovery recording or nothing. If the owner buys J1979-DA later, the §J1979 conventions rows gain section numbers and nothing else changes.
- **Bitmaps promise more than modules deliver.** Module `28` flags `04`–`0B` and `43`–`47`, but it answered `NO DATA` to most of them in local discovery. T0.9 must treat bitmaps as hints. The decoders are unaffected.
- **Modules disagree.** In local discovery, `0130` returned 149 from `17` and 150 from `28`. Results are per ECU; T0.7 decides how to show them.
- **Readiness on EVs (a note for T0.7).** Every Equinox module reports only `components`, complete. Module `17` answers `1C` = 5, "NO OBD" (local discovery). The T0.7 "monitors incomplete" branch must not read an absent monitor as incomplete, or every EV would look "recently cleared".
- **The "masked" rule** labels a real VIN with serial `000000` as masked. Accepted.
- **Unrounded floats** (`69.80392…`). Only the replay rounds, to 3 decimals. The T0.7/T2.6 templates own display precision.
- **Size.** Stage A is M (about half a day), Stage B is M, Stage C is S. Together they make the PLAN's L, in two or three sessions. Stage A goes first. Stage B depends on `response.ts`.
