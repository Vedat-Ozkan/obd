# T2.10a: Exact quantity acceptance contract

## Goal

Close the exact-value bypass in the existing T2.10a checker: a saved response containing an inequality, uncertainty, range, transformed numeric spelling, or uncited quantity must yield the exact offline report template through public `summarize`. Valid exact quantities and individually cited DTCs remain usable. This is one bounded architecture revision and implementation session within T2.10a. The original [T2.10a spec](T2.10a-summary-contract-replay.md) still governs projection, schema, privacy, fallback and verification; this document replaces its unspecified numeric formatting policy. The [task record](../task-runs/T2.10.md) owns authorization and the retained repair history, including 2/2 ordinary repairs.

## Non-goals

- Provider integration, paid calls, OpenRouter setup, mobile, backend, ads, credits, secrets, deployment, and later T2.10 stages.
- Changes to report calculations, projection values, OBD decoding, recordings or signalsets.
- A natural-language parser, synonym model, unit conversion, numeric tolerance, semantic truth proof, or broad language support for numeric statements.
- New dependencies, public API changes, a new task, or resetting repair counters.

## Interfaces

Public signatures and return types in the original spec remain unchanged. `checkSummaryFacts(request, response)` and `checkSummary(report, response)` apply the same policy. `summarize` catches rejection and returns `kind: "template"`, the exact `renderBatteryDiagnosis(caseReport)` text and the existing generic reason. Provider text and errors never appear in that fallback.

### Accepted grammar

Use a small closed grammar for claims containing quantities or DTCs. Do not extract acceptable numeric substrings from otherwise unsupported text. Compare complete bodies against strings formed from the cited facts, then require complete claim coverage. A few string comparisons and delimiter handling suffice; no parser framework, NLP or new abstraction layer is needed.

The following are exhaustive rules, not examples of a broader grammar:

1. **Whitespace:** only leading/trailing ASCII spaces may be discarded from claim text. Internal spacing is literal: one ASCII space at each space shown below. Tabs, newlines, repeated spaces, NBSP, thin/narrow spaces, zero-width characters and Unicode normalization are not accepted in numeric/DTC claims. Inspect raw text before schema trimming can erase unsupported whitespace. Existing schema/citation checks continue to apply.
2. **Quantity `Q`:** exactly `fact.value + " " + fact.unit` from one cited fact. Eligible value spelling is ASCII `-?(0|[1-9][0-9]*)(\.[0-9]+)?`; the optional minus is ASCII and immediately attached. No leading plus, Unicode sign, exponent, leading decimal point, grouping, leading zeroes or trailing decimal point. The spelling must equal the projected value, including sign and decimal digits; `12.70` is not an alias for `12.7`. Eligible units are single tokens matching `[A-Za-z%]+(?:/[A-Za-z%]+)?` and match the cited unit byte for byte and case for case. No aliases or conversion. An ineligible fact spelling cannot authorize a numeric body; other nonnumeric claims may still be checked. This introduces formatting policy, not new OBD measurements or scales.
3. **General quantity body:** `L: Q`, where `L` is that same cited fact's exact label. Eligible labels contain ASCII letters, spaces, parentheses and hyphens only, start/end with a letter or parenthesis, and contain no number or control character. This prevents trusted nominal digits in a label from becoming an exception to quantity checking. Numeric labels can use the explicit compatibility body below if applicable; otherwise their numeric claims fall back.
4. **Existing quantity prose compatibility:** these three bodies, and only these prose bodies, are additionally accepted:
   - `The adapter supply measured Q` for a cited fact whose label is exactly `adapter-supply 12 V supply` and whose unit is `V`.
   - `adapter supply was Q` for the same fact eligibility.
   - `The community cell spread measured Q` for a cited fact whose label is exactly `Cell spread`, unit is `volts`, and tier is `community`.
   Each `Q` still requires that very fact's exact value and unit. These are compatibility forms for existing saved responses, not free-form subjects or verbs. The nominal `12 V` in the request label does not authorize an independently asserted `12 V` quantity.
5. **DTC body:** each `D` must be an exact uppercase identifier matching `[PCBU][0-3][0-9A-F]{3}` and an individually cited fact value. Accept `L: D` with that fact's eligible label. Also accept `Stored diagnostic code D was reported` and `D was stored` only when that fact's label is exactly `stored diagnostic code`. Accept `Stored diagnostic codes D and D were reported` for two distinct individually cited facts with that label. No grouped-value fact, substring match, lowercase code, embedded code, guessed code, or arbitrary letter-plus-digits exemption. Do not infer code meanings. Existing synthetic multi-DTC report overlays remain labeled synthetic.
6. **Complete numeric/DTC claim:** one accepted body, or accepted bodies joined by exactly `; ` or `, and `, followed by exactly one terminal ASCII period. Each body independently resolves to the claim's citations. No additional prefix, suffix, parenthesis, sentence, symbol or prose fragment is permitted. Decimal points belong to `Q`; do not split quantities on periods. A citation to a different same-valued fact cannot authorize a body with another fact's label or compatibility subject.
7. **Prose without numeric symbols:** preserve existing citation/schema/source-ID validation. A claim containing only Unicode letters/marks, ASCII spaces and `. , ; : ! ? ' ( ) -` can remain prose. Any numeric character (Unicode category `N`, including superscripts, fractions and non-ASCII digits), operator or other character removes this route; the entire claim must then satisfy rule 6. Claims with ASCII digits also require rule 6. Do not strip DTCs or quantities and then grant leftover prose an exception. The one exception is a name occurrence of `12 V battery` or `12 V observations` (at the claim start or after an ASCII space or `(`, and at the claim end or before an ASCII space or one of `. , ; : ! ? )`) in a claim that cites at least one fact whose label contains `12 V`: each occurrence is reduced to its noun, and the claim keeps the prose route only if the reduced text has no other numeric character and no character outside the prose set. If anything else numeric remains, the original text must satisfy rule 6, so a name never authorizes a reading. Details: [X-2026-09-29-twelve-volt-name](X-2026-09-29-twelve-volt-name.md).

For example, `The adapter supply measured 12.7 V.` and the existing `P0133 was stored, and adapter supply was 12.7 V.` remain accepted with their existing appropriate citations. General signal statements can use their exact projected label, such as `Cell spread: 0.003 volts.` A negative signal uses the same label form with its exact ASCII negative `Q`; a correct negative literal is not rejected merely for being negative.

Every unsupported numeric form falls back by construction: inserting `±`, `≤`, `>=`, `about`, `at least`, `or less`, `approximately`, or any other prefix/suffix into an accepted body makes it unequal to every accepted body. Likewise, no range, interval, scientific notation or grouped numeric notation is an accepted production. This holds without an expanding modifier-word denylist.

**Boundary:** this policy proves exact lexical quantities and citation resolution under the listed grammar. It does not judge the meaning of prose without numeric symbols (including numbers written as words), detect every misleading omission, or establish diagnosis correctness. BM5's semantic grading remains required. Unsupported numeric phrasing deliberately sacrifices acceptance rate for a checkable rule. Future provider prompts must teach these forms before live use; this amendment does not modify provider scope or authorize calls.

## Risks / open questions

- Largest risk: callers may expect open numeric prose. This contract deliberately narrows that interface to a finite grammar; later provider instructions must teach the canonical label form and supported compatibility forms. Do not expand it during implementation to improve acceptance rate.
- Exact matching preserves current projection rounding, not raw sensor precision. It cannot authorize a claim about uncertainty or sensor accuracy. Numeric word spellings in prose remain a semantic-eval limitation.
- Unit and label eligibility are deliberately limited. A future fact requiring a numeric label, Unicode unit or different notation needs a separately specified format or uses the deterministic fallback; do not silently normalize it.
- The two ordinary repair rounds remain consumed. A new review finding returns to the parent under the recorded continuation; implementation does not invent further repair authorization.
- Prerequisites are the existing tools/dependencies, immutable Equinox fixture and saved-response fixture, all present. No missing source, recording, provider credential or hardware blocks this amendment. No unresolved numeric policy question remains after the parent selected the closed grammar; any proposed relaxation is a material decision for the parent.
