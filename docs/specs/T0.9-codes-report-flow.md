# T0.9: App codes report flow

## Goal

After connecting to the Veepeak, the owner taps one button, **Run codes report**, in the 2024-Equinox-only console screen. The app then does the rest by itself:

- It starts a recording.
- It sends a fixed, sourced command list through the T0.8d capture runner and `ConsoleSession`. The list is init, the Mode 01 bitmaps, readiness, the five report PIDs, Mode 03/07/0A and the freeze-frame DTC.
- It freezes the recording.
- It replays that in-memory recording through `obd-core`'s public entry, `codesReportFromRecording`. That is the same function `pnpm codes-report` uses, moved from the script into `src/report/`. The app then renders the T0.7 codes section under a three-line heading.
- It shows the markdown on screen and opens the Android share sheet for `<date>-codes-report.md`.

The scan stops cleanly and never hangs in these cases:
- `UNABLE TO CONNECT`;
- an unconfirmed `ATZ`;
- a timeout that no `>` follows (stale-until-prompt, as in T0.8d);
- a disconnect.

A partial scan still gives a report when at least one module answered, and the heading says the scan stopped early. The raw recording stays available through the existing **Export recording** button. It stays local until `redact_vin.py` makes the committable copy (ADR-017). The shared report has no VIN, because no VIN request is sent and the renderer never prints one (T0.7 Decision 6).

What a test sees:
- `apps/mobile/test/codes-scan.test.ts` drives the real runner and console over a fake transport. The fake answers from a tracked redacted recording.
- The test asserts that the app's markdown equals the fixed heading plus that recording's block in the committed T0.7 artifact `packages/obd-core/test/codes-reports.md`.
- Isolated tests cover the listed failure modes.

The task has two stages:
- **Stage A** is software only. It runs first and needs no car.
- **Stage B** runs after the owner's Equinox run. It commits the new recording and extends the replay tests with its real counter values. That closes the PLAN verify line.

## Non-goals

- **No PDF** in this task. `expo-print` is a native module that is not in dev client `0f877dca` (see Q1). Markdown only.
- **No native, `app.json`, dependency, or lockfile change.** The only `package.json` edit is one `exports` line in `packages/obd-core/package.json`. It is a workspace path and changes no dependency or lock.
- **No change to the console allowlist** (`READ_ONLY_SERVICES`, `ALLOWED_AT_COMMANDS`, `normalizeReadOnlyCommand`), and no port of `obd-core`'s guard into the console. Every scan command already passes both. The E2E replay goes through `Elm327Session`, so it enforces the guard on the recorded sequence.
- **No change to T0.8d behavior.** **Run capture** keeps its list, rules, and tests. The new runner options default to today's behavior.
- **No change to `buildCodesReport`, `renderCodesReport`, `LOW_COUNTER`, or the verdict.**
- **No bitmap walk and no conditional requests.** The list is fixed. Unsupported PIDs answer `NO DATA`, and the builder marks them `unsupported` from the bitmaps it has.
- **No freeze-frame readings** (`02<pid>00`) and no `020000` (Q3). The report shows `stored for <DTC>` without readings when a frame is stored.
- **No VIN (`0902`), CAL ID, ECU name, `22xx`, `ATDPN`, or `ATRV`.** No Mode 04: this task has no clear path.
- **No storage of reports or scans in the garage, and no garage-level entry point.** The T2.8 gate "every scan and report belongs to a garage vehicle" belongs to T2.6/T2.7. The button lives only on the existing 2024-Equinox-only console screen, behind the same `canUseEquinoxConsole` check as capture (T2.8a spec, Interfaces).
- **No report screen design, no battery data, and no LLM summary** (T2.6, T2.7, T2.10).
- **No automatic second share sheet for the recording** (Q5). No copy into `fixtures/recordings/` and no committing from the app.
- No fix for the T0.8d minor wording finding (`App.tsx` "stopped at step n" after a disconnect between steps). The new heading avoids step numbers, and the capture status line is left alone.

### `apps/mobile/src/capture.ts`: runner options (before → after)

```ts
// before
export function runCapture(session: ConsoleSession, recording: RecordingBuffer, onProgress: (p: CaptureProgress) => void): Promise<CaptureResult>;

// after
export interface CaptureOptions {
  /** Default CAPTURE_COMMANDS. */
  commands?: readonly string[];
  /** Called after each step that produced an outcome and left the ELM idle (a reply with '>', or a late '>' after a
   *  timeout or failed write). A returned string stops the run with that reason. Default: never stops. */
  stopAfter?: (command: string, outcome: string) => string | undefined;
}
export function runCapture(session: ConsoleSession, recording: RecordingBuffer, onProgress: (p: CaptureProgress) => void, options?: CaptureOptions): Promise<CaptureResult>;
```

- `commands` replaces every use of `CAPTURE_COMMANDS` inside the function: the start meta note, the loop, and the stop note.
- `stopAfter` runs in two places:
  - after the progress event of a resolved reply;
  - after `waitForPrompt` returned true on the rejected path, with the error message as the outcome.
- When `stopAfter` returns a reason, the runner sets `stoppedEarly = reason` and breaks. The stop meta note is recorded as today. `sent` counts only writes made.

### `apps/mobile/src/codesScan.ts` (create)

```ts
import type { CaptureResult } from "./capture.js";

/** Fixed list; each entry is already normalized for normalizeReadOnlyCommand and passes obd-core allowedCommand. Sources: this spec §Sources. */
export const CODES_SCAN_COMMANDS: readonly string[] = [
  "ATZ", "ATE0", "ATL0", "ATS0", "ATH1", "ATSP0",
  "0100", "0120", "0140", "0101",
  "0121", "0130", "0131", "014D", "014E",
  "03", "07", "0A", "020200",
]; // 19 commands

/** CaptureOptions.stopAfter for the codes scan. */
export function codesScanStop(command: string, outcome: string): string | undefined;

export interface ReportHeading {
  vehicle: string;      // "<year> <make> <model>" from the CatalogVehicle; never a VIN
  date: string;         // "YYYY-MM-DD", phone local date
  result: CaptureResult;
}

/** Parses the frozen JSONL, replays it through obd-core codesReportFromRecording, and returns heading + renderCodesReport(report).
 *  undefined when no module sent a frame (nothing to report). */
export function codesReportMarkdown(jsonl: string, heading: ReportHeading): Promise<string | undefined>;
```

`codesScanStop` rules. Both apply only to the codes scan; T0.8d capture passes no `stopAfter`.

1. `command === "ATZ"` and `outcome !== "data"` → `"ATZ reset not confirmed (<outcome>)"`. This mirrors the guard. `afterReply` clears the unknown header state only on an `ATZ` answered as data, and a timeout never calls it. Until then `beforeWrite` refuses `ATSP0` (docs/ELM327.md §Write safety, last Input rule; `guard.ts`).
2. `outcome === "error: unable-to-connect"` → `"UNABLE TO CONNECT: no OBD protocol found; check the car is on (Ready) and the dongle is seated"`. Source: docs/ELM327.md §Responses row 3 ("surface to user"). With `ATSP0` every later OBD request would search again, so the run stops.

Otherwise it returns `undefined`.

Markdown returned by `codesReportMarkdown` (exact; `<section>` is `renderCodesReport(report)` unchanged):

```
# Codes report: <vehicle>

Scanned <date> with the phone app. <status>

<section>
```

`<status>` is one of:
- `result.stoppedEarly === undefined`: `Scan complete: <sent> of <total> commands sent.`
- otherwise: `Scan stopped early after <sent> of <total> commands: <stoppedEarly>. Anything not requested shows as "not read".`

### `apps/mobile/App.tsx` (inside `EquinoxConsole` only)

- `localFilename()` becomes `localFilename(slug: string, extension: string)`. The recording export keeps `phone-console`/`.jsonl`. The report uses `codes-report`/`.md`. The `-2`… suffix rule and never-overwrite apply to both.

- The `capture()` handler takes a kind, `capture("recording" | "codes")`. The progress handling is shared and not copied.
  - `"codes"` passes `{ commands: CODES_SCAN_COMMANDS, stopAfter: codesScanStop }`.

  - If it gives `undefined`: status `No module answered; no report. <summary>`.
  - If it throws: status `Report error: <message>`. The recording stays exportable.
  - It does not export the recording automatically. The final status ends with `Tap Export recording to save the raw recording.`
- **Run codes report** button. It has the same enable rule and the same `canUseEquinoxConsole` check as **Run capture**. During the scan, everything except Disconnect is disabled, as in T0.8d.
- The report shows in a scroll view as monospace text. **Share report** re-opens the share sheet for the same text and is enabled when `report` is set. Start recording, Run capture and Run codes report clear `report`.
