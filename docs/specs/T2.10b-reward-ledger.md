# T2.10b: Verified reward ledger and bounded entitlement

Order: after T2.10a and the parent's PLAN/ADR amendments; before T2.10c/d. This stage does not call a model and can be implemented in new files while T2.9 works on `tools/beta-backend` and mobile. It uses a separate Worker and database, so beta upload consent/credentials are never repurposed.

## Goal

Expose an anonymous, HTTPS reward service that exchanges one verified AdMob rewarded completion for exactly one summary entitlement. The backend validates the signed Google server-side verification (SSV) callback, binds it to a short-lived challenge and an anonymous install, rejects duplicates, and atomically consumes credits. No callback, no credit. The deterministic offline report needs no credit.

## Non-goals

- No model call, phone ad SDK, payment, subscription, account, beta upload change, or API-key handling.
- No credit from a phone-only ad callback, ad impression, ad click, or client assertion.
- No assumption that one ad pays for one model call; revenue measurement and production economics are separate.

## Interfaces

```ts
// HTTPS JSON, version 1. Opaque install ID + high-entropy secret created on device.
POST /v1/installs         -> { installId, installSecret } // server generates both
POST /v1/rewards/challenge  Authorization: Bearer <installId>:<secret>
                            -> { challengeId, ssvCustomData, expiresAt }
GET  /v1/rewards/balance    Authorization: Bearer ... -> { available: number }
GET  /v1/rewards/ssv?<Google signed query> -> 200 only after signature and grant processing
// Internal, for T2.10c; no public unauthenticated credit endpoint:
consumeOne(installId: string, requestId: string): Promise<"consumed" | "already-consumed" | "empty">;
```

Use a dedicated Cloudflare Worker with D1 persistence. The server stores only a hash of the install secret. A challenge holds a random opaque nonce, install ID and expiration; the nonce goes into AdMob `custom_data`. Verify Google's ECDSA signature over its specified raw callback bytes using the public key fetched by `key_id`; check allowed key ID, configured ad-unit ID, reward item/amount, callback timestamp/window, challenge nonce and unused state, and globally unique `transaction_id`. A D1 uniqueness constraint and transactional grant make repeated or concurrent callbacks idempotent. Credit is bound to the install and consumed atomically once per request ID. Persist no report, VIN, ad payload beyond minimal audit fields, or IP address; return fixed errors without secrets. Challenges expire and are pruned. The client polls balance while SSV is delayed; a locally reported reward never unlocks a paid call. If ads are unavailable, declined, interrupted or SSV never arrives, the UI later shows the offline report without cost.

Abuse controls before deployment: per-install/day challenge and reward limits, global/day reward and request limits, fixed body-size limits, bounded challenge TTL, and a global kill switch. All limits are **required deploy configuration** and fail closed if absent; production numbers and monthly cost ceiling require owner approval after measured eval. These plus verified SSV, one-use nonce, unique transaction ID and server-side credit consumption are the initial anti-abuse controls. If review finds that anonymous reinstall churn defeats a practical spend cap, add Play Integrity as a separate reviewed prerequisite before public launch; do not silently treat an install ID as person identity. Global spend cap in T2.10c is mandatory regardless.

1. `tools/summary-backend/worker.ts` — endpoints, SSV verification, entitlement operations.

4. `tools/summary-backend/worker.test.ts` — HTTP E2E with an in-memory durable store and signed synthetic callback, authored first.

6. `package.json` — include this backend test in `pnpm test`, after T2.9 releases it.
7. `tsconfig.json` — include summary backend TS, after T2.9 releases it.
8. `eslint.config.js` — include summary backend TS, after T2.9 releases it.

New external dependencies: **none** in source. Cloudflare Worker/D1 is the selected service, configured outside the repo. `wrangler` availability and account setup must be checked before local/deployed gate; if a CLI is added, its pinned version/reason requires a spec amendment and lockfile entry. Google SSV verification uses Web Crypto; do not hand-code ECDSA.

## Verification

Write HTTP E2E tests before Worker logic. No isolated tests are requested: all failure cases enter via the public routes and inspect returned balance/consume results. Synthetic callbacks are labeled synthetic; the test's ephemeral ECDSA key proves verification wiring, not that Google delivered a real ad.

- [ ] `pnpm vitest run tools/summary-backend/worker.test.ts`: create install/challenge, send correctly signed SSV and observe one balance credit; consume it once. Replay SSV, concurrent duplicate SSV, forged signature, wrong ad unit/reward, expired nonce/timestamp, missing challenge, wrong install secret, two concurrent consumes, quota limit and kill switch never create extra usable credit. Emit `/tmp/t2.10b-reward-ledger.json` with scenario names, HTTP statuses, balances and no secrets.
- [ ] `pnpm check` and `git diff --check` pass after T2.9 releases root files; confirm `pnpm check` actually includes this Worker's test and source in TS/lint. The reviewer runs the explicit command above regardless. Python Ruff/pytest remain part of `pnpm check`; no Python changes.
- [ ] Real AdMob SSV: configure a test ad unit and Google callback in an owner-controlled AdMob account, show an ad in a development build, and save a redacted trace of challenge ID, callback acceptance, one credit and one consumption in `/tmp/t2.10b-live-ssv.json`. If account/config are absent, report **NOT RUN** and T2.10 remains incomplete; this is an external-service gate, not vehicle hardware-only.
- [ ] Deployed HTTPS Worker/D1 and its binding/secret check are **NOT RUN** until the owner authorizes deployment and configures accounts/limits. A local test is not deployment evidence.

## Risks / open questions

- Largest risk: entitlement fraud or callback races could turn one ad into many model calls. The reviewer must inspect unique constraints and atomic consume behavior, not only sequential tests.
- D1/SSV real setup and its dependencies must be verified before implementation. T2.9 currently owns root `package.json`, `tsconfig.json`, `eslint.config.js`; do not edit those concurrently. This stage's root-file work waits until their release; no `pnpm check` waiver is allowed.
- Owner must choose production daily/monthly caps, account/service setup, retention period and whether Play Integrity is required for launch. Install limits alone do not stop repeated reinstall.
