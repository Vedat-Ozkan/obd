# T2.8b: garage gates (first-connect model check)

## Goal
PLAN T2.8 lists four gates after T2.8a. Audit of main (2026-10-24): gates 2 and 3 are already met (table below). Gate 1 is open. This task closes it: before the battery diagnosis scan reads any battery module, the app reads the car's VIN (`0902`, a Mode 09 read, already in `READ_ONLY_SERVICES`) and compares the maker code (VIN chars 1-3) and model-year code (char 10) to the values recorded for the selected verified model. On a mismatch, or when no VIN is read, the scan stops, no report is saved, and the user is told the car does not look like the selected model. Test-visible outcome: a replay of the real Equinox VIN answer passes; a replay with a different year code returns `model-not-confirmed` and saves nothing.

## Non-goals
- No change to gates 2, 3 or 4, and no garage-list tier tag.
- No model identification for beta rows. They stay blocked from battery data (`canUseEquinoxConsole`); a model-year VIN rule needs a recording from that model first (hard rule 1).
- No general VIN-year table or VIN decoder for other makes.
- No change to `obd-core` (pure; `decodeVin` is used as is) and no new dependency.
- No check on the "Log a charge" path (see Open questions 5).
- No persisted "confirmed" flag per car; the check runs on every battery scan.
- No VIN shown in the UI, stored in the report, or sent anywhere new.

## Interfaces
```ts
// apps/mobile/src/garage/catalog.ts
// before: CatalogVehicle = { id; make; model; year; tier; recording? }
// after:  adds an optional field, set only on the verified 2024 Equinox EV entry
type CatalogVehicle = { /* existing */ vinIdentity?: { wmi: "3GN"; yearCode: "R" } };

export type ModelCheck = { status: "match" } | { status: "mismatch" | "unconfirmed"; reason: string };
export function checkVehicleIdentity(vehicle: CatalogVehicle, vins: readonly string[]): ModelCheck;
// match: vehicle has vinIdentity, vins is non-empty, and every vin has vin.slice(0,3)===wmi and vin[9]===yearCode
// mismatch: some vin differs; unconfirmed: vins empty or vehicle has no vinIdentity

// apps/mobile/src/batteryScan.ts
// before: runBatteryDiagnosisScan(transport, recording, onProgress): Promise<DiagnosisRun>
// after:  extra param; sends "0902" right after init and before the 0120.. loop,
//         decodes the VIN frames with decodeVin (obd-core), calls confirm(vins).
//         A non-match stops the scan before any Mode 22 read.
runBatteryDiagnosisScan(transport, recording, onProgress, confirm: (vins: string[]) => ModelCheck): Promise<DiagnosisRun>;
// DiagnosisRun gains: identity?: ModelCheck   (set only when status !== "match")

// apps/mobile/src/batteryDiagnosisFlow.ts: result union gains
| { status: "model-not-confirmed"; reason: string }
// returned before keepScan, before history.save; no scan file is kept
```
`reason` wording is the implementer's, but it names the selected model and says the car did not answer as that model (mismatch) or that the model could not be confirmed (unconfirmed); it never contains a VIN character.

## Risks / open questions
Implementation may proceed on every recommended default below (they are the safest option and the PLAN test column already says block).
1. Unreadable VIN (`NO DATA`, timeout, or no `0902` support). Block (recommended): treated as "could not confirm", user can retry. Alternative: continue and rely on the existing CB SOC fingerprint. Proceed on block.
2. What happens to a mismatched scan's data. Recommended: nothing kept, nothing queued for beta, because the beta label would carry the wrong `catalogId`. Proceed on this.
3. User override on mismatch (for example the year was picked wrong). Recommended: no override; the PLAN tests say mismatch blocks, and the user can add the right model year. Proceed on this.
4. "First connect" literally versus every battery scan. Recommended: every battery scan (one extra command, no stored flag). Proceed on this.
5. "Log a charge" is not covered. Recommended: leave it; ADR-022 keeps the charge log paused and owner-only, and the same entry gate applies. A later task can reuse `checkVehicleIdentity`.
6. Please confirm gates 2 and 3 are accepted as MET, including the two cosmetic caveats in the audit. If the owner wants a garage-list tier tag or per-car foldering of raw charge-log files, that is a separate small task.
7. Risk: the 3GN / R rule is one vehicle's evidence. A 2024 Equinox EV from another plant or trim is expected to share the maker code and year code, but only one VIN is committed. Hard rule 1 prevents a wider rule; an owner test on a second 2024 Equinox would reduce this.
