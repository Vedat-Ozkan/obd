# Hardware spike, September 2026 (T0.2)

Filled by the user after the car sessions from the rows `tools/spike/spike.py` prints and the meta line of each recording. Spec: `docs/specs/T0.2-hardware-spike.md`. Every cell starts as `NOT RUN`; replace it with an outcome or `NOT RUN: <reason>`.

## EV-first quick run (short laptop session)

The EV answers Gate A on its own. The ICE cars are optional bench vehicles and do not need recordings for Phase 0 (ADR-015). You only need to bring back the EV `.jsonl` file. The per-car tables below preserve the original spike worksheet; unrun ICE rows remain NOT RUN.

**At the desk, once, with internet (about 10 min):**

1. Install `uv`. Windows (PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`. macOS/Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`. Open a new terminal afterwards.
2. `git clone https://github.com/Vedat-Ozkan/obd.git` then `cd obd`. The script is a single self-contained file (`tools/spike/spike.py`) if cloning is awkward.
3. `uv run tools/spike/spike.py --help`. This downloads Python and `bleak` now, so the car session needs no downloads.
4. If the Veepeak is paired in the OS Bluetooth settings, remove it. Charge the laptop.

**At the car (about 15 min):**

1. Plug in the dongle. Car powered on and **Ready**, in Park. Note the SOC % on the dash; it checks the SOC signal later.
2. In the `obd` folder, run `uv run tools/spike/go.py`. Press Enter for the Equinox (the default), then type the dash battery % and the outside temperature. It finds the dongle, picks a new file name (`<today>-spike.jsonl`, or `-spike-2` if that exists), and runs the test. If it lists several devices, choose the Veepeak by number.
3. Watch the rows scroll by; it takes 1–3 minutes. Any row with `6227C6`, `622AF5`, or `622B43` means the battery data is readable.
4. If many rows show `timeout`, run it again as `uv run tools/spike/go.py --timeout 8`. It saves to a new file automatically; keep both.
5. Unplug the dongle when done (12 V drain on the EV).
6. Optional, about 5 min per car if time allows: the same `go.py` command, choosing 1 (Chrysler) or 2 (Elantra), with ignition on and engine off.

**Afterwards:** copy the `.jsonl` file to the desktop as a file (USB, cloud drive, email attachment, or a push from the laptop) and say where it landed. Don't open and re-save it in an editor. The bridge reachability check (section 2) is no longer needed now that the phone is the bridge (ADR-013).

## How to run (at the car, on the laptop)

Once: clone the repo, install `uv`, make sure the dongle is not paired in the OS Bluetooth settings. Per car: plug the dongle in, put the car in the state you will write in `--note` (ICE: ignition on, engine off; EV: powered on / ready), then:

```text
uv run tools/spike/spike.py --scan
uv run tools/spike/spike.py --car chrysler-200-2013        --address <addr> --out fixtures/recordings/chrysler-200-2013/2026-09-<dd>-spike.jsonl        --note "<state>"
uv run tools/spike/spike.py --car hyundai-elantra-2019     --address <addr> --out fixtures/recordings/hyundai-elantra-2019/2026-09-<dd>-spike.jsonl     --note "<state>"
uv run tools/spike/spike.py --car chevrolet-equinox-ev-2024 --address <addr> --out fixtures/recordings/chevrolet-equinox-ev-2024/2026-09-<dd>-spike.jsonl --note "<state>"
```

Optional flags: `--timeout <s>` (default 20; lower it if the EV never finds a protocol under `ATSP0`; after a timeout the printed rows for the following command may be misattributed, because a late `>` can satisfy the next wait early: the recording is the authority, and an `rx` line may precede the next `tx` line), `--interactive` (type extra read-only commands after the fixed list; empty line ends). A second run the same day goes to `<date>-spike-2.jsonl`. If a run fails part-way, keep the partial file under a `-partial` name and rerun into a new `--out`; never edit a recording. Paste the printed rows into the tables below. Bridge reachability check: on the laptop `cd tools/hil-bridge && uv sync --frozen && uv run uvicorn hil_bridge.app:app --host 0.0.0.0 --port 8000`; in WSL2 `curl http://<laptop-lan-ip>:8000/` should return `{"service":"hil-bridge","status":"ok"}`.
