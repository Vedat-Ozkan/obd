# T2.14: Parked scan upgrade

## Goal

One fresh 2024 Equinox EV battery check keeps the existing codes and battery reads, then records three cycles of the existing `CHARGE_LOG_PROFILE` while the car is parked. Its saved report shows one complete set of 80 cell-group voltages at rest, a separately labeled BMS figure from `CB/27AF` energy remaining divided by `CB/2B43` SOC, and the raw `CB/2AF1` response. It cites the same private scan recording for each value. The BMS figure is a comparison reported by the car's battery system, not independently measured capacity. A prior scan still opens with the new fields absent. The opt-in assistant's `prepareSummaryRequest` facts and ratings stay identical for the same legacy observations.

## Non-goals

- No cell-group fault or red-flag verdict, policy limit, coverage list, or change to rating chips (T2.15).
- No temperature conversion, per-sensor name or inferred byte layout, or temperature agreement claim without a checked-in source (T2.17). Preserve the full positive `2AF1` payload as raw hex.
- No independent capacity estimate or change to `capacity.status: "not-measured"`, `health.status: "not-assessed"`, the paused overnight charge log, or its estimator.
- No drive capture or report, UDS `19` reads, new vehicle command, vehicle write, manufacturer module expansion, BLE or foreground-service change, summary prompt, fact projection, or assistant tool change.
- No hand edits to `fixtures/recordings/`; the extended full-scan fixture is explicitly synthetic.

## Interfaces and behavior

Keep the current `runBatteryDiagnosisScan`, `runAndSaveBatteryDiagnosis`, `batteryDiagnosisFromRecording`, `parseBatteryDiagnosis`, and `renderBatteryDiagnosis` public signatures. Existing reports stay `version: 1` and parse unchanged. The changes are additive:

```ts
// obd-core's first-party Equinox evidence overlay, in obdb/equinox.ts:
// withEquinoxEv2024Evidence(imported) additionally supplies one verified
// CB/27AF, unsigned 16-bit / 100 kWh signal. It is NOT an upstream OBDb row.

// obd-battery/report:
interface ParkedScan {
  groupVoltages?: {
    volts: readonly number[];       // exactly 80, recording order
    modules: readonly number[];     // exactly 80, from the same complete set
    sources: readonly ReportSource[]; // the seven CB/2AE1..2AE7 reads
    completeSets: number;           // retained complete sets in this recording
  };
  bmsFigure?: {
    valueKwh: number; energyKwh: number; socPercent: number;
    tier: "verified";
    energySource: ReportSource; socSource: ReportSource;
  };
  temperatureRaw?: { payloadHex: string; source: ReportSource };
}
interface BatteryDiagnosisReport { parked?: ParkedScan }
```

The persisted shape above is the contract; parked observations do not enter `report.signals`. The BMS energy definition belongs in the first-party Equinox evidence overlay, with a `recording` and `check` that say the *direction and changes* were corroborated in the targeted watch; the absolute energy level and capacity implied by division remain unverified. `27AF` is used only with a valid positive `18DAF1CB` response and `2B43` SOC from the same charge-profile cycle, with SOC greater than zero. Reuse T2.4's `bmsEnergyCapacity` pairing semantics and its BMS label; choose the last valid pair in the scan. It is a **BMS figure**, never `capacity` or a certified pack size. Display its input energy and SOC, units, verified-on-car measurement tier with the narrower evidence explanation, and the recording/commands. The bounded byte-resolution band from T2.4 is not a total error band and need not appear in this short-scan report.

After the existing generic codes scan and **unchanged** `equinoxEv2024Profile`, `runBatteryDiagnosisScan` records a `parked scan start` meta marker, then calls public `scanMode22Profile(session, CHARGE_LOG_PROFILE)` three times sequentially, using the same guarded session and recording transport. Three is a scan-duration policy for the plan's “few cycles,” not an OBD constant. The marker marks the new profile reads as parked-only evidence; do not add `27AF` to the legacy `equinoxEv2024Profile`. Preserve today's stop-on-classified-ELM-error, partial scan, private keep, SOC fingerprint, and interruption behavior. A `NO DATA` reply leaves that field absent; never fabricate an observation. The scan's `complete` status means the request sequence ended, not that all three parked fields were obtained.

In `batteryDiagnosisFromRecording`, feed the actual replayed Mode 22 replies to the existing `ChargeLogBuilder` (or an equivalent use of its public parsed output), while keeping the same one-recording boundary. On a newly marked scan, only reads **before** `parked scan start` enter legacy `signalReadings`/`report.signals`; all reads after it supply parked fields only. An old recording without the marker retains its existing legacy signal handling, except `27AF` is always excluded from `report.signals` because its display belongs in the BMS figure. This preserves the legacy summary projection for the new scan; the source-backed `27AF` overlay can decode without becoming an assistant fact. Choose the latest complete 80-record `2AE1`–`2AE7` set whose nearest preceding and following `17/2414` current samples from these cycles are both within the existing T2.4 `REST_CURRENT_A` magnitude. This bracket is the report's operational “at rest” criterion; a missing current bracket or incomplete group set leaves `groupVoltages` absent. Never use the nearest `2AF5` min/max as a substitute for the 80 records. Keep the record order and module IDs; no threshold or flag is computed. Use the latest valid `CB/2AF1` positive response's payload bytes as uppercase hex. A negative, truncated, wrong-header or wrong-echo response leaves the raw field absent. The report does not call those bytes degrees or identify a sensor position. The report renderer and the existing cell/capacity detail view show the additions, with explicit “not read”/“not available at rest” states on old and partial reports; keep the four summary rows and their ratings. `parseBatteryDiagnosis` validates finite positive group voltages, exactly 80 aligned module IDs in the recorded module range, the seven same-recording group sources, finite positive BMS inputs and result, raw even-length hex, and all nested recording labels. Old reports without `parked` pass. E2E persistence checks submit invalid nested recording labels and malformed parked values through the public report parser and history save/load boundary; they fail visibly.

## Risks / open questions

- Largest risk: the first actual phone parked scan may not supply two low-current samples around a complete group set. Software replay and the targeted recording prove decoding but cannot prove the parked acceptance gate; the owner car run remains hardware-only.
- `27AF` changing in line with load validates its response and slope on one car, not the absolute kWh basis. The report must never turn `27AF` ÷ SOC into `capacity.status: measured`, an error-banded capacity estimate, or a health verdict.
- A `2AF1` positive response establishes bytes, not which byte is which sensor. ADR-023's “sensors' agreement” cannot be quantified from this source and remains deferred pending a checked-in layout/recording; T2.17 also needs a cold-soak comparison before °C.
- Three cycles add time and additional failure opportunities after the existing scan. Partial status and private recording retention must survive late errors and cancellation. A completed request sequence can still lack one of the new fields.

## Decisions

- T2.14 is desk-ready under the owner's existing authorization. The chosen scan policy is three sequential `CHARGE_LOG_PROFILE` cycles; at-rest selection requires bracketing `17/2414` samples under T2.4's `REST_CURRENT_A`. These are implementation policy, not new vehicle constants.
- Add `27AF` in the first-party checked-in evidence overlay, with a narrow verified claim about the observed energy change and an explicit absolute-level limitation. Do not edit the vendored OBDb signalset.
- Keep the new profile's reads outside `report.signals` using a recording meta boundary, and keep `27AF` out of `report.signals` on older recordings. The assistant fact projection and ratings remain unchanged for the same legacy observations. The deterministic report renderer may include parked fields; the assistant fallback renders that report on an invalid model response.
- Raw `2AF1` means the full positive payload in hex. No sensor split, agreement number, or unit is specified without a sourced layout.
