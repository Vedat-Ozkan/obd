# T0.4: `Elm327Session`: init, protocol fallback, single-flight queue, timeouts, retries, ISO-TP reassembly, ECU routing

## Goal

Add the layer between `ElmLineReader` (T0.3) and decoders (T0.5, T2.1). `Elm327Session` wraps an injected `Transport` and does five things. It runs the init sequence, choosing a protocol and falling back to auto search if a fixed one fails. It sends one command at a time, first in first out. It enforces a timeout on each command and resyncs after one. It retries the ELM errors that `docs/ELM327.md` says to retry. It returns every response as ISO-TP messages reassembled per ECU header, for both 11-bit and 29-bit IDs, with a defined result for every frame it cannot use.

What a test sees when this is done:
- `session.init()` replays the tracked Equinox spike recordings byte for byte (`ATZ` through the `SEARCHING...` `0100`) and reports 29-bit IDs from five ECUs.
- `0902` returns two 20-byte VIN messages, from ECUs `17` and `28`.
- `090A` returns `BUFFER FULL` with the one message that was complete before the overflow.
- The stray consecutive frame that leaks into the following `03` reply is dropped with a named reason.
- `0A` returns per-ECU negative responses.
- A labeled synthetic fixture covers the fixed-protocol fallback, 11-bit headers, a timeout, and the retry branches.
- `pnpm replay <recording.jsonl>` prints the reassembled frames for each command, with the VIN payload redacted.

## Non-goals

- **No decoding.** Nothing is decoded: no PID values, VIN text, DTCs, bitmaps, ECU names, or ATDPN or ATRV semantics beyond passing the text line through. That is T0.5.
- **No Mode 22 profile machinery.** No `ATSP7`/`ATCP`/`ATSH`/`ATCRA`/`ATFCSH` setup built into profiles, no per-module headers in `VehicleProfile`, no OBDb import. That is T2.1. The session carries these commands only as raw `send()` strings, which is how the replay tests use them.
- **No automatic re-init.** The session does not re-init after `LV RESET` or a desync. It surfaces the condition, and the caller calls `init()`.
- **No reassembly across responses.** A message cut off by `BUFFER FULL` is not continued from the next response's leftover frames. Those frames are dropped (see ISO-TP rules).
- **No `ATAT1`/`ATST`/`ATCAF1`** in init. They are optional in `docs/ELM327.md` and absent from every recording, so adding them would break the byte-exact replay.
- **No new response classes.** `classifyLine`/`parseElmResponse` (T0.3) stay unchanged. No new rows in `docs/ELM327.md`.
- **No interpretation of negative-response codes** (for example `78` response pending). There is no recording of one. `Frame.negative` exposes the service and code bytes, nothing more.
- **Transports and packaging stay as they are.** No BLE, relay, or HTTP transport, no app wiring, no `obd-core` `exports` changes. The replay script imports by relative path.
- **No Mode 04 path.** T0.7 adds the confirmed clear (see open question 2).
- **No logging** anywhere in `packages/obd-core/src`.

### `src/elm/isotp.ts` — create — pure, stateless per call

```ts
/** One reassembled ISO-TP message from one ECU (name kept from ARCHITECTURE.md; it is a message, not a CAN frame). */
export interface Frame {
  header: string;     // CAN ID as printed, spaces removed: "7E8" or "18DAF117"
  ecu: string;        // "17" when header is 18DAF1xx, otherwise the header itself ("7E8")
  data: Uint8Array;   // payload with PCI bytes removed, trimmed to the ISO-TP length (padding dropped)
  negative?: { service: number; code: number };  // present iff data[0] === 0x7F and data.length >= 3
}

export type DropReason = "no-first-frame" | "sequence" | "incomplete" | "flow-control" | "malformed";

export interface DroppedFrame {
  header: string;
  reason: DropReason;
  line: string;       // the line as received (for "incomplete": the first-frame line)
}

export interface Reassembly {
  frames: Frame[];         // in order of their single-frame or first-frame line
  dropped: DroppedFrame[]; // in detection order; end-of-response "incomplete" entries last, in first-frame order
  text: string[];          // content lines that are not frame-shaped (e.g. "ELM327 v1.5")
}

/** Pure. `lines` = the content lines of ONE response (ElmRawResponse.lines), headers on (ATH1). */
export function reassemble(lines: readonly string[]): Reassembly;
```

**Frame-shaped line.** Remove spaces. The line must be hex (`/^[0-9A-F]+$/i`). The header width follows from the parity of the length, because every data byte is two hex characters. An **odd** length means an 11-bit header of 3 characters. An **even** length means a 29-bit header of 8 characters. The data after the header must be 1 to 8 bytes. Any other line goes to `text`. Consequences, both intended and both pinned by tests:
- `A0` (ATDPN) and `12.7V` are text.
- The truncated line before `BUFFER FULL`, such as `18DAF1282` (9 characters), parses as header `18D` with PCI `0xA` and is dropped as `malformed`. That is harmless, and it is the recorded behavior.

**PCI rules**, from the first data byte (`docs/ELM327.md` §Multi-frame). State is kept per header and starts empty for every response.

| High nibble | Meaning | Handling |
|---|---|---|
| `0` | single frame, low nibble = length L | If `1 <= L <=` the bytes present, emit a `Frame` of the next L bytes. Otherwise drop as `malformed`. Does not touch any message in progress for that header. |
| `1` | first frame, 12-bit length `((b0 & 0x0F) << 8) \| b1` | If this header already has a message in progress, drop it as `incomplete`. Start a new message with the bytes after the two PCI bytes. Expected sequence = 1. If the collected bytes already cover the length, complete it at once. |
| `2` | consecutive frame, low nibble = sequence | **No message in progress for this header: drop as `no-first-frame`.** This is the stray frame seen after `BUFFER FULL`. If the sequence does not equal the expected value: drop the partial message and this frame as `sequence` (two entries), and clear the header's state. Otherwise append the 7 bytes and set expected = (expected + 1) & 0xF, so the sequence wraps F → 0. When collected ≥ length, emit a `Frame` trimmed to length and clear the header's state. |
| `3` | flow control | drop as `flow-control` (the ELM sends flow control itself; we never expect to receive one) |
| other | — | drop as `malformed` |

At the end of the lines, every message still in progress is dropped as `incomplete`, in first-frame order.

`ecu`: `/^18DAF1([0-9A-F]{2})$/i` → the captured pair; otherwise the full header.

### `src/elm/session.ts` — create

```ts
import type { ElmError } from "./errors.js";
import type { DroppedFrame, Frame } from "./isotp.js";

export interface SendOptions {
  timeoutMs?: number;   // default DEFAULT_TIMEOUT_MS; measured from just before transport.write()
  retry?: boolean;      // default true; `pnpm replay` passes false (recordings from the Python tools contain no retries)
}

interface ResponseBody {
  frames: Frame[];          // [] for AT commands
  dropped: DroppedFrame[];  // [] for AT commands
  lines: string[];          // AT commands: all content lines; others: Reassembly.text. Non-printable lines removed (see below)
  searching: boolean;
  raw: string;              // verbatim text of the final attempt, '>' excluded
  attempts: 1 | 2;
}

export type ElmResponse =
  | ({ kind: "data" } & ResponseBody)
  | ({ kind: "ok" } & ResponseBody)
  | ({ kind: "nodata" } & ResponseBody)
  | ({ kind: "error"; error: ElmError } & ResponseBody); // frames kept: BUFFER FULL still returns complete messages

export interface InitResult {
  protocol: VehicleProfile["protocol"];  // the ATSP value in effect after init ("0" after a fallback)
  fellBack: boolean;
  idBits: 11 | 29;                       // from response0100.frames[0].header length (3 → 11, 8 → 29)
  voltage: string | undefined;           // ATRV content line as printed ("12.7V"); undefined if ATRV was not data
  response0100: ElmResponse;             // kind "data", frames.length >= 1; T0.5 reuses it instead of re-sending 0100
}

export type SessionErrorKind = "timeout" | "closed" | "blocked" | "init";

export class ElmSessionError extends Error {
  readonly kind: SessionErrorKind;
  readonly command: string;
  readonly response?: ElmResponse;  // "init": the response that failed the step
}

export const DEFAULT_TIMEOUT_MS = 5000;
export const CAN_ERROR_RETRY_DELAY_MS = 500;
export const RESYNC_MS = 1000;

export class Elm327Session {
  constructor(transport: Transport);  // subscribes to transport.onData once
  init(profile: VehicleProfile): Promise<InitResult>;
  send(cmd: string, opts?: SendOptions): Promise<ElmResponse>;
  close(): Promise<void>;
}
```

**Changes to the ARCHITECTURE.md sketch.** `raw` becomes a single `string`, matching T0.3's `ElmRawResponse.raw`. Every variant carries the frames, dropped frames, lines, the `searching` flag, and the attempt count. `ok` is its own kind. `Frame.header`/`ecu` are required, because headers are always on, and `Frame` gains `negative`. The shape is otherwise kept: `init`/`send`/`close`, and `kind` as the discriminant. The ARCHITECTURE.md block is updated to match (Files).

#### Resolve vs reject

- **Resolves:** the ELM answered with a `>`, whatever it said, including every `ElmError` kind.
- **Rejects with `ElmSessionError`:**
  - `timeout`: no `>` within `timeoutMs`.
  - `closed`: close() ran before or during the command.
  - `blocked`: see Write guard.
  - `init`: a required init step failed.
- **Also rejects:** a `transport.write` rejection propagates as-is. The session treats that like a timeout for resync purposes.

#### `send(cmd)` behavior, exactly

1. **Write guard.** Remove spaces and uppercase the command. If it does not start with `AT` and its first two characters are `04`, `2E`, `2F`, or `31`, reject with `blocked` without writing anything (AGENTS.md hard rule 5; open question 2).
2. **Queue.** Commands are FIFO and single-flight. A command's bytes are written only after the previous command has settled, including its retries and any resync wait. `init()` runs as one queue item, so `send()` calls made during init run after it.
3. **Resync.** If the previous command timed out or its write failed, the session is *stale*. Before writing, wait until a `>` arrives or `RESYNC_MS` passes, whichever comes first. Discard whatever arrived, clear stale, and write. If a `>` arrives while no command is in flight, the session also discards it and clears stale.
4. **Write.**
   - Call `reader.reset()`, which clears any partial text, matching T0.2's "clear the receive buffer" step.
   - Start the timeout timer.
   - Write `latin1Encode(cmd + "\r")`. `cmd` is written verbatim: no trimming or case change. `ReplayTransport` matches bytes exactly.
5. **Complete.**
   - The first completed reader segment settles the command, through `parseElmResponse(raw, cmd)`.
   - Any further segments completed in the same push, and any segment completed while nothing is in flight, are discarded.
   - Drop every content line that contains a character outside `0x20`–`0x7E`. This is the clone's reset garbage `ü` (spike line 4, spike-2 line 3; `docs/ELM327.md` §Clone quirks). It stays in `raw`.
   - AT commands (normalized form starts with `AT`) get `frames: []`, `dropped: []`, `lines` = content lines. Every other command goes through `reassemble`.
   - `kind` comes from `ElmRawResponse.status`.
6. **Retry (once, only if `opts.retry !== false`).** The retry is the same command, written again through step 4, inside the same queue slot:
   - `can-error`: wait `CAN_ERROR_RETRY_DELAY_MS`, then retry.
   - `data-error` (`DATA ERROR` or `<DATA ERROR`): retry immediately.
   - `kind === "data"` with a dropped entry whose reason is `incomplete` or `sequence`: retry immediately. This covers the clone quirk "drops the last line before `>`". `BUFFER FULL` is `kind: "error"`, so it never triggers this retry, which is correct: the same request would overflow again.
   - No other retries. `NO DATA`, `UNABLE TO CONNECT`, `BUFFER FULL`, `STOPPED`, `?`, `LV RESET`, `BUS INIT`, `ERRnn` and timeouts are surfaced as they are.
   - The response returned is the second attempt's, with `attempts: 2`.
7. **Timeout.** Reject with `timeout` and mark the session stale. Timeouts are not retried: sending while the ELM is busy aborts it with `STOPPED` (§Framing).

#### `init(profile)` sequence, exactly

This is the order in both tracked Equinox recordings (spike lines 2–41, spike-2 lines 2–41). It is `docs/ELM327.md` §Init sequence plus `ATI`.

| # | Command | Required outcome | On failure |
|---|---|---|---|
| 1 | `ATZ` | any response ending in `>`; content ignored (reset banner and clone garbage) | timeout rejects |
| 2 | `ATI` | any (version string is decoration, §Clone quirks) | tolerated |
| 3–6 | `ATE0`, `ATL0`, `ATS0`, `ATH1` | `kind === "ok"` | reject `init`, `command` = the step |
| 7 | `ATSP<profile.protocol>` | `ok` | reject `init` |
| 8 | `ATDPN` | any; not interpreted (it answers `A0` before the first search: spike line 21) | tolerated |
| 9 | `ATRV` | any; `voltage` = `lines[0]` if `kind === "data"` | tolerated |
| 10 | `0100` | `kind === "data"` and `frames.length >= 1` (`SEARCHING...` allowed) | see fallback |

**Fallback.** If step 10 fails and `profile.protocol !== "0"`, the session sends `ATSP0`, which must return `ok`, and then `0100` once more. It sets `fellBack: true` and `protocol: "0"`. If `0100` still fails, or failed under `"0"` in the first place, init rejects with `init`, `command: "0100"`, and that response. Retries (step 6) apply inside each step as usual. `init()` clears the stale flag and resets the reader before step 1.

**The protocol is inferred from the reply headers, not from `ATDPN`.** Before the first request `ATDPN` only says `A0` (spike line 21). A second `ATDPN` after the search would break the byte-exact replay of both tracked recordings, and there is no recording of its reply. The width of the reply headers (`18DAF1xx`) is the recorded evidence of 29-bit IDs.

#### `close()`

1. Clears any timeout, retry-delay, or resync timer.
2. Rejects the in-flight command and every queued one with `closed`.
3. Unsubscribes from the transport and calls `transport.close()`. The session owns the transport it was given.
4. Is idempotent.
5. After it runs, `send`/`init` reject with `closed` without writing.

It sends nothing to the dongle.

#### VIN and privacy

The session returns VIN bytes only inside `Frame.data`. It never logs, formats, or stores them. There is no `console` in `src/`. `pnpm replay` redacts them (below). Tests assert the VIN's structure without writing the VIN as a literal in test source; T0.5 owns VIN decoding and its test. ADR-014: the VIN stays on the device.

### `packages/obd-core/scripts/replay.ts` — create — Node-only, outside `src/` (purity kept)

```ts
/** Runs every tx of a recording through Elm327Session.send (retry: false, timeoutMs: 500) and formats the result. */
export function replayRecording(lines: readonly RecordingLine[]): Promise<string[]>;
// main (only when run as a script): read argv[2] with node:fs as latin1, parseRecording, print lines, exit 0;
// usage error → exit 2; parse error or ReplayMismatchError → message on stderr, exit 1.
```

- The replay does not call `init()`. It sends each recorded `tx` verbatim, with the trailing `\r` stripped, so any recording replays whatever init sequence it used. That matters because the discovery recordings have no `ATI`.
- Timeouts print as `timeout` and the replay continues. The session's resync wait applies.
- Recordings made by the Python tools contain no retries, hence `retry: false`.

Output format, one block per `tx`:

```
L<line> <cmd> -> <kind>[ <error.kind>][ searching][ attempts=2]
  <header> <data as space-separated hex>[ negative service=<hh> code=<hh>]
  dropped <reason> <line>
  text <line>
L<line> <cmd> -> timeout
summary: <n> commands; data <n>, ok <n>, nodata <n>, error <n> (<kind>=<n>, ...), timeout <n>; frames <n>; dropped <reason>=<n>, ...
```

**VIN redaction.** When the normalized command is `0902`, each frame prints as `<header> 49 02 <N bytes redacted>`. Dropped and text lines print as `dropped <reason> <header> <redacted>` and `text <redacted>`.

Root `package.json`: `"replay": "tsx packages/obd-core/scripts/replay.ts"`, so `pnpm replay <path>` works from the repo root.

## Risks

- **`RESYNC_MS` is a policy guess.** A `>` arriving more than 1 s after a timeout would be attributed to the next command. That is the known T0.2 misattribution, now bounded but not removed. Mode 01 and Mode 22 positive replies echo the PID or DID, so T0.5 and T2.1 decoders should check the echo before trusting a value. Hardware may justify a different value; change it only with a recording.
- **Retry on `incomplete`/`sequence`** doubles traffic on a flaky link (bounded to one retry). It never fires on `BUFFER FULL`.
- **Functional `090A` overflows** on the Equinox, so four of five ECU names are lost. Per-message reassembly cannot fix that. T0.5/T2.1 should request `090A` per module with `ATCRA`, as discovery did.
- **Parity-based header width** assumes `ATH1`. A caller that sends `ATH0` through `send()` gets nonsense frames. Only malformed or dropped frames result, never a wrong complete message of the right length, because the length comes from the PCI.
- **`ATI` in init** is not in the `docs/ELM327.md` list. It is kept because both tracked recordings have it, and the recording is the authority. It costs about 25 ms. The gitignored discovery recordings omit it, so they replay through `pnpm replay` (raw sends), not through `init()`.
- **Fake timers and microtasks.** `ReplayTransport` delivers with `queueMicrotask`. Tests must advance timers with the async variant (`vi.advanceTimersByTimeAsync`).
- **Size L, about one day.** The split point is Stage A / Stage B.
