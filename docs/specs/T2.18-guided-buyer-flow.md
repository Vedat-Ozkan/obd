# T2.18: Guided buyer flow

## Goal
A buyer who has run a parked check on a `checked` garage car can, from that report, tap "Add a short drive". The drive check starts as a third check intent (no vehicle-state note to type, no Developer tools), ends by itself, and Stage C's codes rescan runs. The screen then asks the user to park and offers the existing "Run battery check" for the post-drive parked scan, which saves a normal parked report with its red-flag verdict. The drive report (already pointing at the pre-drive report) is listed under the car's report history and reopens from there. The drive group rule keeps its "not yet confirmed" label (ADR-023, T2.13 Stage C); this task does not flip it.

## Non-goals
- Flipping `GROUP_RULE_STATUS` (waits for R1) or any retuning of the rule.
- Folding the drive finding into the red-flag outcome. T2.15's `redFlagScreen` and `BatteryDiagnosisReport` are unchanged; the drive finding stays provisional and out of the verdict.
- An automatic full parked scan right after the drive ends (see Q1; default is a prompted tap).
- Any new command, `19` service reads (T2.16), temperature (T2.17), AI summary of the drive.
- Changing `driveCapture.ts`, `obd-core`, `obd-battery`, or the drive report format (all are used as merged in Stage C).
- Linking the post-drive parked report to the drive report in the parked report's schema.
- A "withdrawn" rule state, the simulated car (X-2026-10-24-simulated-car), any new dependency.

## Risks / open questions
1. **Parked rerun: automatic or by tap?** The drive may stop at the cap while the car is still moving. A scan run then would measure cell groups under load, and `redFlagScreen`'s limits were set at rest; no at-rest current limit is sourced (hard rule 1). Recommended default: after the drive ends the screen says "Park the car, then run the battery check" and the user taps the existing button. The PLAN row's "reruns" is met by one tap, not by timer. Changing this needs a sourced rest criterion first.
2. **Should the post-drive parked report cite the drive report?** Default: no. `BatteryDiagnosisReport` stays untouched (one schema, one parser, T2.15 tests); the drive report already cites its pre-drive report, and the history is time-ordered.
3. **Which parked report may start a drive?** Default: only the one `preDriveReport` would pick (latest, same day), so D14 holds unchanged and the "Add a short drive" button is hidden on older reports. If the owner wants a drive from an older report, D14 must change first.
4. **Codes are read twice** (drive rescan and the post-drive parked scan). Default: keep both; ADR-023 has each report cite only its own recording, so merging them would break that.
5. **Drive length.** Default: keep 10 and 20 minute buttons, 20 first, as in Stage C; a single fixed length is a smaller screen but changes T2.13's contract.
6. **Ownership gate.** Default: show the drive button on `mine` entries too (same parked-report precondition); the PLAN row names `checked` only for the owner run.
