## Interfaces / design

Public Worker and package interfaces stay as defined by the governing C1 spec. The setup contract is:

```bash
pnpm dlx wrangler@4.142.0 --version
pnpm check
```

In `.github/workflows/check.yml`, remove `XDG_CACHE_HOME` from job-level `env`: GitHub excludes `runner` from that expression context. Make the first step a named cache initialization step, before checkout, pnpm setup, setup-node cache handling or any tool preparation. Its complete run body is:

```bash
printf 'XDG_CACHE_HOME=%s/t210-ci-cache\n' "$RUNNER_TEMP" >> "$GITHUB_ENV"
```

The runner supplies `RUNNER_TEMP`; writing the environment file makes this value available to every subsequent step, including actions and separate shells. The initialization step does not need to consume the newly assigned variable itself. Preserve the named pinned-Wrangler preparation step after workspace installation and before `pnpm check`. Keep the existing Node 22.13.0, pnpm 9.15.9, Python, uv and frozen workspace/bridge installs. Disable Wrangler metrics for preparation with `WRANGLER_SEND_METRICS: 'false'` (job or step environment); tests already disable them. No cache restore is required for this tool. Failure preparing the exact version must fail setup.

`cachedWrangler()` continues to inspect manifests under `${XDG_CACHE_HOME}/pnpm/dlx` and execute the exact cached `node_modules/wrangler/bin/wrangler.js` directly. Its already implemented missing-cache prerequisite diagnostic and runtime fixture logic remain the governing C1 behavior; this correction requires no harness change.

The backend README already describes a shared temporary cache. Change its CI sentence only if it directly describes the invalid job-level expression: say CI initializes `$RUNNER_TEMP/t210-ci-cache` through `$GITHUB_ENV` before tool setup. Existing owner preparation commands remain valid. CI setup and owner CLI preparation may install the approved Wrangler tool; test execution may not.
