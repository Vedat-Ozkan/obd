# T2.5a: Recorded 12 V observation and condition-gated advice

## Goal

Create the first, pure `obd-battery` package and a reusable 12 V report section. Replay committed redacted Equinox recordings through `Elm327Session`, show their `ATRV` voltage with its source and Ready context, and say **12 V battery health not assessed**. Accept a module's standard Mode 01 PID 42 reading when one exists, but label it control-module supply voltage. A separate, explicitly documented rested AGM terminal-voltage input may produce only a recharge-check advisory; it must never turn an in-car `ATRV` or PID 42 reading into a battery-health verdict. The CLI output is the repeatable report artifact and the section is reusable by T2.6/T2.7.

This is a bounded software stage of PLAN T2.5. T2.5b adds the app reminder after T0.9 releases `apps/mobile/`. Do not mark the whole task done from this stage alone.

## Non-goals

- No new car query or change to the vehicle guard, ELM session, report/codes, T0.9 scan, `apps/mobile/`, or recordings. In particular, no 12 V measurement while the car is off: asking `ATRV` requires a powered dongle and may wake/load the car.
- No 12 V battery state-of-health percentage, replacement verdict, charge percentage, fault diagnosis, or extrapolation from the Ready-state trace. The 2026-09-23 owner observation (11.7–13.6 V in Ready) is not a threshold calibration.
- No automatic use of the Interstate OCV threshold on `ATRV` or PID 42. Neither measures an open-circuit battery terminal.
- No user-entered rested-voltage UI or battery service procedure. Only a typed optional input for a future owner-supplied, documented independent measurement; no such real measurement exists in committed fixtures.
- No T2.6 battery report screen, capacity, or codes-section integration.

## Interfaces

`packages/obd-battery/src/twelve-volt.ts` is pure TypeScript and exports named declarations:

```ts
export type VehiclePowerState = "ready" | "other" | "unknown";
export interface TwelveVoltObservation {
  source: "adapter-supply" | "module-supply";
  command: "ATRV" | "0142";
  volts: number;
  ecu?: string; // required in practice for 0142; never fabricated for ATRV
  powerState: VehiclePowerState;
  recording: string; // relative redacted/synthetic fixture path or caller's local recording label
}
export interface RestedAgmOcv {
  source: "independent-terminal-voltmeter"; // never ATRV or 0142
  chemistry: "AGM";
  volts: number;
  restHours: number;
  vehicleOff: true;
  noChargerOrLoad: true;
  surfaceChargeRemoved: true;
  temperatureC: number;
  measurementNote: string; // who/when/how, required; do not invent
}
export interface TwelveVoltReport {
  observations: readonly TwelveVoltObservation[];
  batteryHealth: "not-assessed";
  /** An OCV recharge-screening advisory, not a health or replacement decision. */
  rechargeAdvice: "not-assessed" | "recharge-and-retest" | "no-recharge-flag";
  reason: string;
}
export function buildTwelveVoltReport(
  observations: readonly TwelveVoltObservation[],
  restedOcv?: RestedAgmOcv,
): TwelveVoltReport;
export function renderTwelveVoltReport(report: TwelveVoltReport): string;
```

- `buildTwelveVoltReport` rejects non-finite/non-positive input voltages, a `0142` observation without `ecu`, wrong command/source pair, and a rested input missing any required measurement condition or note. That protects the public boundary without adding a dependency. It does **not** infer battery health from either in-car source.
- The deterministic OCV gate requires the complete typed `RestedAgmOcv` record, at least **24 h** since charge/discharge, and independently measured voltage at the terminals with car off and no charger/load. Temperature is retained and printed, because voltage depends on it. The only advice is `recharge-and-retest` for `< 12.64 V`, or `no-recharge-flag` for `>= 12.64 V`; either way `batteryHealth` remains `not-assessed` and text says a load test/service assessment is needed for health. The 24 h gate is conservative from BU-903; `12.64 V` is the Interstate AGM OCV recharge threshold, not an EV/Ready-state threshold. A value with insufficient rest/conditions is rejected or returns `not-assessed` with the reason, never silently eligible.
- The renderer prints one line per observed voltage, including source (`ELM adapter supply` or `control-module supply`), `ATRV`/`0142`, ECU where present, recorded state, and a recording label. Missing readings render `12 V voltage: not recorded`; every report prints `12 V battery health: not assessed` and the reason. It does not print a guessed SOC or aggregate unlike-source voltages.
- `packages/obd-battery/scripts/twelve-volt-report.ts` is the Node-only public replay CLI. For each supplied `*.redacted.jsonl` (or explicitly synthetic) path it calls `parseRecording`, replays every `tx` through `Elm327Session` + `ReplayTransport` with `retry:false`, collects only `ATRV` responses and valid PID `0142` frames (`decodePid(0x42, frame)`), calls the builder and renderer, and prints a deterministic report block headed by the input path. It treats unknown power state as unknown; the two spike meta notes explicitly say `ready`. It accepts no OCV input from JSONL and emits no VIN/raw reply. Timeout handling follows `codesReportFromRecording`'s existing replay pattern. Exit nonzero on replay mismatch or invalid input. No vehicle write or invented query is introduced.
- CLI argument `--rested-ocv` is **not** part of this stage. The typed OCV branch is proven with labeled synthetic values in an E2E report-builder test; it is dormant until a real independent measurement is documented.

### Failure modes listed before code (covered by E2E scenarios, no isolated test file)

1. Malformed `ATRV` or missing PID 42 frame becomes a plausible numeric reading → replay/report output must omit the reading and say not recorded for that source; no fabricated zero.
2. The same numeric volts from `ATRV` or PID 42 is classified as AGM battery health/OCV → real/synthetic replay output always says `not-assessed` without an independent measurement.
3. A rested OCV declaration has too little rest, active load/charger, wrong chemistry/source, missing note, or non-finite volts → public builder rejects or returns `not-assessed`, never threshold advice.
4. The threshold boundary is rounded first or interpreted as a replacement/health verdict → synthetic report-builder artifact shows `<12.64` vs `>=12.64` recharge advice and `batteryHealth=not-assessed` in both.
5. Mixed ECU/adapter readings are merged or an unsourced PID value is parsed ad hoc → synthetic PID 42 replay keeps ECU/source and uses `decodePid`'s checked-in J1979 table; real `ATRV` remains separate.

### Hardware-only / unavailable evidence

- **NOT RUN**: Independent rested, unloaded, documented terminal measurement of the actual installed AGM battery. The car must have been off long enough to satisfy the 24 h gate, with no charger/load; a connected/waking dongle is not the measuring instrument. Record the battery label/chemistry, temperature, time since charge, measurement instrument, and raw voltage if the owner elects this later. Do not treat this as a prerequisite for the honest in-car observation report.
- **NOT RUN**: A real Equinox PID 42 response. `0142` is standard but no committed redacted Equinox recording answers it. Show only the synthetic branch until a new redacted recording supports a vehicle claim.

## Risks / open questions

- The owner's wide Ready-state `ATRV` trace shows that 12 V regulation and load are dynamic. The report must not imply that 11.7 V in Ready is proof of a weak battery. The cause of that trace is unverified.
- Original chemistry is AGM/VRLA per GM, but a replacement could differ. The OCV gate requires a documented installed AGM battery; the manual alone cannot authorize an OCV assessment of a replaced battery.
- Interstate's OCV threshold is a recharge-screening step for its AGM batteries. Even a value above the threshold is **not** proof of health; the manufacturer proceeds to a load test. Keep advisory wording narrow.
- T0.9's `apps/mobile/` work is concurrent. The mobile reminder is a later T2.5b stage with a fresh baseline, not an edit in this stage.
