# T0.10b: Evidence-backed protocol observation labels

## Goal

Give each of the three committed redacted 2024 Equinox EV recordings and each of the three existing synthetic recordings a companion label for **observable replay outcomes**. A label names its immutable input, marks whether it is synthetic, and records selected command outcomes and the full replay summary. A label-driven E2E test replays every labeled input through the public `replayRecording` entry point; `pnpm test` also replays every committed redacted recording through the existing recording test. The six CLI summaries are repeatable artifacts. This completes the evidence-backed observation-label portion of T0.10; the full plan item stays open because no available capture supports a healthy battery baseline.

## Non-goals

- Do not call any real capture `condition: healthy` or `fault`, infer capacity/state of health, create a charge-session reference, or treat no DTC/MIL as a battery-health finding. The two spikes and phone console are short protocol snapshots; they have no independent health or capacity reference.
- Do not force the three synthetic protocol fixtures into the `docs/EVAL.md` health-session schema. Their synthetic errors, DTCs, and readiness values are decoder examples, not battery fault or healthy cases.
- Do not implement `obd-eval`, a production label reader, a new decoder, or a new hardware capture. Do not change recording bytes, synthetic JSONL bytes, or the redaction script.
- Do not edit the shared plan/decisions or pre-existing T0.5 Stage C files: `docs/ELM327.md`, `packages/obd-core/scripts/replay.ts`, `packages/obd-core/src/obd/freeze.ts`, or its test. Do not edit `packages/obd-core/src/elm/guard.ts`, `tools/relay/`, or the T0.6 worktree.

## Interfaces

No runtime TypeScript API changes. Each companion is `<recording stem>.replay-label.json`, next to the recording. For a real `*.redacted.jsonl`, remove `.redacted.jsonl` before adding `.replay-label.json`; for a synthetic `*.jsonl`, remove `.jsonl`. This suffix is distinct from the future `*.label.json` session labels in `docs/EVAL.md`.

The test-only JSON contract is:

```json
{
  "kind": "protocol-replay",
  "recording": "fixtures/recordings/chevrolet-equinox-ev-2024/2026-09-24-phone-console.redacted.jsonl",
  "recording_sha256": "e87dab6c101d35cc89a00b1594ff121b626eaeee6826ddbd33db5e7ab8acbe3d",
  "synthetic": false,
  "observations": [
    { "tx_line": 18, "command": "0100", "outcome": "data searching", "decoded": ["  decoded 17 supported 01 0D 1C 1F 20"] }
  ],
  "summary": "summary: 10 commands; data 5, ok 5, nodata 0, error 0, timeout 0; frames 12; dropped none",
  "notes": "Protocol observations only; no battery-health adjudication."
}
```

`tx_line` is the one-based recording line number of the recorded `tx`; `command` is its `data` without the final CR and must be copied from that line. `outcome` is the exact text after `->` in the `L<tx_line> <command> -> ...` replay heading. `decoded` is an array of selected exact `  decoded ...` lines within that command block; use `[]` if no decoder applies. `summary` is the exact final `summary: ...` line. The test must validate field types, a nonempty observations array, the companion path and SHA, the recording's `synthetic` metadata versus label, and each observation against the replay output. No VIN or identifying payload goes into a label or test failure message. `notes` is a short evidence limitation, not a free-form vehicle diagnosis.

Each real label uses `synthetic: false` and cites only its redacted recording. Each synthetic label uses `synthetic: true` and cites its own metadata plus its originating spec. The real labels may repeat factual capture context such as Ready/Park or the spike's **dash-displayed** 70% SOC and 14 °C ambient if the note explicitly attributes it to recording metadata; none is a battery-health label. Keep notes brief and avoid extra measured numbers that the label test cannot verify.

## Risks / open questions

- **Largest risk:** protocol responses could be presented as battery health evidence. The distinct suffix, `kind`, README wording, and explicit no-health field rule prevent that interpretation. Readiness `mil=off`, empty DTC lists, and a displayed SOC are limited observations.
- The `pnpm test` real-recording discovery currently reads local ignored originals, including discovery files. Narrow its selection before running the full suite, then confirm with the reviewer. This is a privacy and reproducibility prerequisite, not a reason to edit or inspect the originals.
- T0.5 Stage C edits to replay output are pre-existing and concurrent. If a selected decoded line changes before implementation, rederive that observation from the same redacted fixture and public output and return any material semantic change to the orchestrator; do not edit the T0.5 files.
- Open for **full T0.10**, not for T0.10b: which real measurement and independent adjudication will justify `condition: healthy`, and when can that capture be made? No current file answers it.

## Decisions

1. Owner approved labels for observations in the three committed redacted recordings and the existing synthetic cases, while deferring a healthy baseline until health evidence exists. Full T0.10 remains OPEN; T0.10b cannot be presented as the plan gate's completion.
2. Use test-only `*.replay-label.json` companions for protocol observations so future `docs/EVAL.md` `*.label.json` health-session consumers do not mistake them for schema-valid condition labels. No `condition`, `reference`, or `fault` field appears in these companions.
3. The six JSONL files remain byte-identical. Only committed redacted real fixtures are read by this task's tests and verification commands.
