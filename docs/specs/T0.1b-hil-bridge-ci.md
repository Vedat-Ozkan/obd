# T0.1b: HIL bridge hello world and CI

## Goal

Add a minimal `uv`-managed Python 3.11+ FastAPI service for `tools/hil-bridge`, integrate its lint and test checks into the root `pnpm check`, and add GitHub Actions that installs both locked toolchains and runs that command. This is the second ordered T0.1 spec. T0.1 software is ready for review when all local checks pass, but the plan's literal clean-clone and pushed-CI gates remain pending until the user authorizes an initial commit and push.

## Non-goals

- Do not add BLE, `bleak`, dongle discovery, ELM commands, `/status`, `/cmd`, recording endpoints, raw-byte endpoints, or any vehicle interaction; T0.6 owns the bridge behavior.
- Do not add an OBD transport, fixtures, recordings, TypeScript product code, mobile code, deployment configuration, containers, or release packaging.
- Do not edit planning, architecture, decisions, agent setup, task-run, README, or the T0.1a spec.
- Do not install tools system-wide, commit, push, publish, or claim hosted CI ran when it did not.
- Do not weaken `pnpm check` when `uv`, Python 3.11+, network access, or dependencies are missing.

## Interfaces

The local service command is:

```text
cd tools/hil-bridge && uv run hil-bridge
```

It starts a development HTTP server on loopback and exposes only:

```http
GET /
```

with status `200` and exact JSON:

```json
{"service":"hil-bridge","status":"ok"}
```

The Python package exports `app` for ASGI use and a typed `main() -> None` console entry point. The implementation remains import-safe: importing the module must not start the server.

After this sub-spec, the root command surface is:

```text
pnpm check          # TypeScript typecheck + lint + Vitest, then Python ruff + pytest
pnpm check:ts       # the T0.1a TypeScript checks only
pnpm check:bridge   # uv-run ruff and pytest under tools/hil-bridge
```

GitHub Actions runs on pushes and pull requests. It checks out the repository, installs Node `22.13.0`, pnpm `9.15.9`, Python 3.11, and `uv`, installs with `pnpm install --frozen-lockfile` and `uv sync --frozen`, then runs the single contract command `pnpm check`. The workflow must not require secrets, hardware, Bluetooth, or a running server.

## Files

Seven implementation files: two created or updated at repository level and five created under the bridge.

- `package.json` — update root scripts so `pnpm check` covers both the TypeScript workspace and the bridge without changing T0.1a dependencies.
- `.github/workflows/check.yml` — create the push/PR workflow using locked installs and `pnpm check`.
- `tools/hil-bridge/pyproject.toml` — create Python requirement, runtime/dev dependencies, console script, build metadata, pytest settings, and ruff settings.
- `tools/hil-bridge/uv.lock` — create with `uv`; never hand-author it.
- `tools/hil-bridge/src/hil_bridge/__init__.py` — create the package marker without extra API.
- `tools/hil-bridge/src/hil_bridge/app.py` — create the FastAPI app, hello route, and console `main`.
- `tools/hil-bridge/tests/test_app.py` — create the HTTP-level hello-route test.

## Dependencies

Resolve and lock package versions with `uv`; do not guess transitive versions. Keep runtime and development groups separate.

| Dependency / tool | Scope | Reason |
|---|---|---|
| Python `>=3.11` | prerequisite and project constraint | Required baseline for the bridge scaffold; the available Python 3.10.12 is insufficient. |
| `uv` | prerequisite, not a project dependency | Mandated Python environment and lockfile manager; it is currently absent from PATH. |
| `fastapi` | runtime | Defines the ASGI application and hello route. |
| `uvicorn` | runtime | Runs the `hil-bridge` console command locally. |
| `hatchling` | build system | Builds/installs the `src/`-layout package so the console entry point works under `uv run`. |
| `pytest` | development | Repository-standard Python test runner for the bridge. |
| `httpx` | development | Required by FastAPI/Starlette's HTTP test client used to verify the public route. |
| `ruff` | development | Required Python lint command. |
| `actions/checkout` | CI action | Makes repository contents available to the job. |
| `actions/setup-node` | CI action | Installs the specified Node runtime and enables pnpm caching where supported. |
| `pnpm/action-setup` | CI action | Installs the specified pnpm version. |
| `actions/setup-python` | CI action | Installs Python 3.11 for the bridge. |
| `astral-sh/setup-uv` | CI action | Installs `uv` using its maintained GitHub Action. |

Use the current stable documented major release of each official GitHub Action at implementation time and record the chosen refs in the implementation report. Do not add `bleak`, production process managers, type checkers, coverage tools, or FastAPI's broad optional extras.

## Verification

Prerequisites before implementation checks:

- [ ] `uv --version` succeeds. If `uv` must be installed, request the necessary permission and follow the official installation method; do not alter repository files beyond this spec.
- [ ] `uv python install 3.11` (or an already-installed Python 3.11+ interpreter selected by `uv`) succeeds. Do not use the available Python 3.10.12 for the locked environment.
- [ ] Registry/network access is available for initial pnpm and uv resolution. A denial leaves dependent checks NOT RUN.

Implementation and review checks:

- [ ] `cd tools/hil-bridge && uv lock --check` succeeds after the generated lockfile exists.
- [ ] `cd tools/hil-bridge && uv sync --frozen` succeeds.
- [ ] `cd tools/hil-bridge && uv run ruff check .` succeeds.
- [ ] `cd tools/hil-bridge && uv run pytest` succeeds and `tests/test_app.py` verifies the exact `GET /` status and JSON over FastAPI's HTTP test client.
- [ ] `cd tools/hil-bridge && uv run hil-bridge` starts without import or entry-point errors; stop it after a loopback request confirms the exact response. This is local software verification, not hardware verification.
- [ ] `pnpm install --frozen-lockfile` succeeds at the repository root.
- [ ] `pnpm check` succeeds and visibly executes TypeScript typecheck, ESLint, all three empty Vitest suites, Ruff, and pytest.
- [ ] Workflow inspection confirms triggers for push and pull request, locked installs, exact required runtimes, no secrets/hardware, and `pnpm check` as the final contract command.
- [ ] Pre-commit clean-copy check: copy only the intended repository contents (excluding `.git`, dependency directories, caches, and generated virtual environments) to a new `mktemp -d` directory; there run `pnpm install --frozen-lockfile`, `cd tools/hil-bridge && uv sync --frozen`, then root `pnpm check`. Report this as a clean-copy PASS, never as a clean-clone PASS.
- [ ] `git status --short` confirms existing setup files remain untouched and changes are limited to both T0.1 specs' implementation files, the architect-authored specs, and the orchestrator-owned task record.

Post-implementation task gates that cannot honestly run before an initial commit/push:

- [ ] **NOT RUN until user-authorized initial commit:** clone that commit into a new temporary directory and run `pnpm install --frozen-lockfile`, `cd tools/hil-bridge && uv sync --frozen`, and root `pnpm check`. This is the plan's literal clean-clone verification.
- [ ] **NOT RUN until user-authorized push:** inspect the GitHub Actions run for that pushed commit and confirm the `check` workflow is green. Local workflow inspection is not CI execution.

The reviewer must report the two post-implementation gates as NOT RUN with these reasons and must not call the full T0.1 plan item complete until both become PASS. They are not hardware-only exceptions.

## Risks / open questions

- The largest risk is environmental: `uv` is absent and the installed Python is below the required version, so the bridge lockfile and complete `pnpm check` cannot be produced without installing/selecting prerequisites and resolving packages.
- The repository has no initial commit. The clean-copy check detects undeclared local dependencies but cannot prove the clean-clone gate; only a later user-authorized commit can make that test possible.
- Hosted CI cannot be verified without a remote push. A syntactically plausible workflow is not evidence that Actions is green.
- No hardware is needed. Bluetooth, the Veepeak dongle, cars, and recordings first become relevant in later tasks.
- No material design question is open. If installation policy prevents obtaining `uv` or Python 3.11+, stop with that concrete blocker rather than changing the toolchain.

## Decisions

- T0.1b is ordered after T0.1a and owns the final root-check integration and CI workflow.
- `pnpm check` is the single local and CI quality gate and includes the Python bridge; `pnpm check:ts` and `pnpm check:bridge` remain diagnostic subcommands.
- The hello-world API is intentionally only `GET /`; using a future architectural endpoint name such as `/status` would prematurely consume T0.6 scope.
- Use Python 3.11 as the CI baseline while allowing any compatible `>=3.11` interpreter locally through `uv`.
- Treat clean-copy, clean-clone, and hosted CI as three distinct evidence levels. Before the first commit/push, only clean-copy can pass.
- Routine scope is authorized by the selected automatic architect → implementer → reviewer workflow. No user choice is required before implementation; installing missing prerequisites may still require sandbox approval.
