# T2.1b: Equinox 29-bit profile scan

## Goal

Add a pure `obd-core` Equinox profile and public scan function that sends the recorded 29-bit CAN setup and Mode 22 requests in module order, preserving each response and the module that produced it. Replay the two committed Equinox spike tails through `Elm327Session` and show the same three `DACB` replies and one `DA1D` `NO DATA` without contacting hardware. This sub-spec is implementable from the committed redacted recordings **without** the OBDb vendor/import work in T2.1a; do it first if pinned upstream source acquisition is blocked.

## Non-goals

- Importing or decoding named/scaled OBDb signals (T2.1a), promoting tiers or matching dash values (T2.2), app/relay integration, adding unrecorded vehicle modules, or changing the guard's allowlist.
- A generic configuration language for arbitrary AT commands. The API accepts only two-digit module targets and two-byte Mode 22 DIDs; it derives the safe setup commands itself.
- Changing `Elm327Session.init()` or its existing generic fallback. A caller may initialize with the existing generic profile for the standard scan, then run this profile scan to switch to ATSP7, as in the spike recording.

## Interfaces

Before:

```ts
interface VehicleProfile { protocol: "0" | "6" | "7" }
```

After:

```ts
export interface Mode22Module {
  readonly target: string;       // exactly two uppercase hex digits; e.g. "CB"
  readonly dids: readonly string[]; // exactly four uppercase hex digits, recorded read requests
}
export interface VehicleProfile {
  protocol: "0" | "6" | "7";
  mode22?: readonly Mode22Module[];
}
export const equinoxEv2024Profile: VehicleProfile;

export interface Mode22Outcome {
  target: string;
  did: string;
  response: ElmResponse;
}
/** Sends ATSP7 and the recorded setup, then one guarded 22 request per DID. */
export function scanMode22Profile(session: Elm327Session, profile: VehicleProfile): Promise<readonly Mode22Outcome[]>;
```

`equinoxEv2024Profile` has `protocol: "7"` and two modules in recorded order: `1D/33E5`, then `CB/27C6,2AF5,2B43`. The constant comes directly from the committed recording, independently of OBDb's `dbgfilter`. The scanner validates the complete profile before the first write, refuses a profile with Mode 22 entries unless its protocol is `7`, and derives only:

```text
ATSP7, ATCP 18,
per target: ATSH DA<target>F1, ATCRA 18DAF1<target>, ATFCSH 18DA<target>F1,
once after the first flow-control header: ATFCSD 300000, ATFCSM 1,
22 <DID> for each DID in that target.
```

It awaits `OK` for every setup command before proceeding, aborting on `?`, error, or timeout. A `NO DATA` read remains an outcome; a read error remains an outcome and is never converted into a reading. `Elm327Session` already enforces the read-only allowlist, one command at a time, and ISO-TP reassembly; the scanner does not duplicate those layers. It does not emit a VIN or raw response text to user-visible output. A generic profile without Mode 22 entries returns an empty array without changing the dongle.

## Files

- `packages/obd-core/src/vehicles/profile.ts` — modify; typed modules and the Equinox constant sourced from the recordings.
- `packages/obd-core/src/vehicles/scan.ts` — create; validate the profile, send derived setup/requests, preserve outcomes.
- `packages/obd-core/scripts/profile-scan-replay.ts` — create; Node-only CLI: parse a supplied committed redacted Equinox recording, select its contiguous tail beginning at recorded `ATSP7`, run `scanMode22Profile` over `ReplayTransport`, print command/DID status, reply ECU and payload length (no VIN or raw bytes), and a deterministic summary. Exit nonzero on replay mismatch or invalid profile. This is the repeatable E2E artifact command.
- `packages/obd-core/test/profile-scan.test.ts` — create; recording-backed E2E checks plus the one synthetic branch below.
- `fixtures/synthetic/profile-setup-failure.jsonl` — create; explicitly labeled synthetic recording of `ATSP7` `OK`, `ATCP 18` `?`, with no Mode 22 TX; this branch has no real recording.

Five implementation files. No new dependencies. `node:fs` and `node:path` are used only in the Node CLI/test, never under `src/`. T2.1a's separate files and `scripts/replay.ts` do not need to exist for this sub-spec.

## Risks / open questions

- **Largest risk:** the scanner could issue a request under the wrong 29-bit header. The exact ReplayTransport match on both real tails and the guard's existing sequence check are the review gates.
- The first spike has a previous `090A` buffer-full event, but the Mode 22 tail is intact. Slice only from the recorded `ATSP7` tx, never modify or copy the recording file.
- A generic session's earlier `ATSP0` is outside the tail. The scanner explicitly sends `ATSP7`; it does not assume the prior protocol state. `Elm327Session` keeps its existing init contract.
- A cloned dongle could reject a setup command. The synthetic branch requires an abort, and the live result remains hardware-only.

## Decisions

- This spec may be implemented and reviewed **before T2.1a**, using only the committed redacted recordings. It does not require the upstream OBDb signalset or license.
- Keep profile scan results raw and sourced; T2.1a adds name/scaling/tier interpretation from OBDb after the exact vendor pair is available.
